# 本地观战器 P0

## 用途

这是与赛事进程隔离的独立程序。它只尾随已落盘的审计记录（`AuditRecord`，Bot 异步写出的脱敏事实），在浏览器显示一个 Token 身份可见的手牌、公开牌桌、桌内积分、规则候选和最新增量事件。

它不读取运行配置、不持有 Token、不请求官方平台，也不实现动作提交。因此观战器崩溃、关闭或读取失败不会影响官方场次的动作窗口。

P0 的可见性固定为单一玩家观察（`PlayerObservation`，本家手牌与公开信息）。测试房间的四视角合并和赛后牌谱导入属于后续阶段。

## 启动

推荐从任意目录执行仓库自带启动脚本：

```bash
./scripts/run_spectator.sh
```

脚本会先切换至仓库根目录。未显式传 `--watch-dir` 时进入**跟随模式**：脚本把
`artifacts/sessions/` 作为赛事父目录交给服务端（`--follow-live-sessions`），
服务端在运行时按「`runs/` 子树最新一次写入」自动发现仍在进行的批次（兼容
`<会话>/runs` 与 `<会话>/audit/runs` 两种层级），因此**自由赛换批后会自动接入
新批次，不需要重启观战器**。

- 重新发现每 5 秒做一次；最多同时跟随 2 个批次，用于覆盖「旧批次刚停、新批次
  刚开」的过渡；超过 30 分钟没有写入的批次会被移出跟随列表。
- 判定只看 `runs/` 子树：赛后仍在写 `postgame/` 的已结束批次不会被误当成进行中。
- 启动时会在终端提示当前跟随到的批次；没有活跃批次时提示等待换批。
- 用 `--watch-dir` 显式指定目录则不进入跟随模式，行为与以前一致（固定观察该目录）；
  其余参数照旧透传，例如 `./scripts/run_spectator.sh --port 8766`。
- 找不到 `artifacts/sessions/` 时回退到服务端默认 `./runs`。

也可以在仓库根目录直接执行：

```bash
python3 spectator/server.py
```

默认审计目录是仓库根目录下的 `./runs`，服务仅监听 `http://127.0.0.1:8765/`。浏览器页面每 750 毫秒请求一次本机快照；观战程序会增量读取 JSONL 尾部，不反复扫描已读原始事件。

用 `--watch-dir` 可选择其他审计目录，也可重复指定多个目录。显式传入后只观察指定目录，不会混入默认 `./runs`。观战器自动识别以下任意层级：

- 单个运行目录：`.../runs/{run_id}/`；
- 普通赛事或自由赛的 `audit_root`（其下有 `runs/{run_id}/`）；
- 测试房间父目录（其下有 `slot-*/runs/{run_id}/`）。
- 已归档测试房目录：`bot-audit/{角色}/run-*/`（例如 `xuanwu/run-*`）。

例如，测试房间可以直接传入统一父目录：

```bash
python3 spectator/server.py --watch-dir ./room-runs
```

仓库内现有测试房归档可直接这样查看：

```bash
python3 spectator/server.py \
  --watch-dir ./game-records/test-room/20260906-1444-t_74a7c2d75d5e/bot-audit
```

P0 目前只面向实时观战，不列出历史牌局：它会排除已经记录 `game_finished` 或完整
观察已处于 `phase=finished` 的官方场次。页面先按去重后的“活跃官方场次”选择
`game_id`，再只列出该场次有审计的“观战角色”（测试房间 `slot-*`、归档角色目录如
`xuanwu` 或审计 `participant_id`）。同一场次被四个 Token 同时记录时也只出现一次，
因而可在 `M > 1` 时先切换场次、再切换视角。

排查目录识别时可只输出一次 JSON，而不启动网页：

```bash
python3 spectator/server.py --watch-dir ./room-runs --once
```

## 界面速览

- 视觉主题对齐商业麻将客户端：近黑底 + 金色描边 + 绯红强调；牌桌为深绿毛毡加深木外框，
  **牌张直接铺在桌面上**（不做逐座位的方框面板），中央是深色风盘（余牌大字 + 门风 + 局数）。
- 座位是圆形芯片：自绘头像 + 门风芯片（庄家为金色高亮）+ 庄/行动中/财神徽章 + 桌内积分，
  分数按正负着色（正绿负红），侧栏场次卡片同样着色。
- 头像由本项目自绘（`static/assets/avatars/`），不代表任何真实玩家形象；官方快照也不提供
  对手身份，芯片只用于区分座位。
- 界面按「游戏窗口」排布：**左侧场次栏 / 中间牌桌 / 右侧决策信息栏**，页面本身不滚动
  （`body` 固定视口高度，各栏内部按需滚动）。
- 牌桌按可用区域**等比缩放**：`app.js` 的 `fitBoard()` 先量出牌桌原始尺寸与可用区域，
  取 `min(可用宽/牌桌宽, 可用高/牌桌高)` 作为缩放比，然后把 `#board-frame` 撑成「缩放后
  尺寸」、牌桌以左上角为原点 `scale()`。这样视觉尺寸等于布局尺寸，居中与完整性由普通
  布局保证，不依赖 `overflow` 裁剪。窗口尺寸、栏位变化都会触发重算（ResizeObserver +
  resize 事件，合帧处理）。
- **易踩的坑**：`.board-fit` 的栅格轨道必须写成 `minmax(0, 1fr)`。若用默认 `auto` 轨道，
  轨道最小尺寸会取子项的 min-content（牌桌固定 1000px 宽），轨道自身溢出容器，牌桌就被
  顶偏到右侧、底部被裁掉——表现为「牌桌不居中、不完整、手牌被截断」。
- 响应式断点：1440px 与 1220px 逐档压缩两侧栏宽度，980px 以下退化为上下单列布局并
  允许整页滚动（小窗口与移动端兜底）。
- 活跃场次在左侧栏以卡片列表呈现（不再是下拉框），每张卡显示桌号、局数、财神×N、
  我方分数，以及「待我响应／轮到我」标记；排序为「本家财神张数降序 → 我方积分降序 →
  场次名」，点击即切换牌桌。财神牌取 rule_state.wealth_god（当前规则固定为白）。
- 刷新为增量更新：轮询到内容未变时不重建 DOM，只有选中牌桌的快照、候选或提交变化时
  才重绘该牌桌，其他桌只在原位更新文字。因此页面不再每 750 毫秒闪烁一次，滚动位置
  和选中状态也保持稳定。
- 牌桌仿实体麻将桌，每个座位由外向内依次是「牌墙（暗手）→ 副露 → 牌河」，牌河紧贴
  中央：上下两家每行 6 张、左右两家两列（按行填充，等价旋转 90°）；最近一张弃牌橙色
  发光，悬停显示第几张。中央为风盘，显示四家门风（以庄家为东）、牌墙余量与当前局数，
  两侧并排显示规则状态与桌面事实。
- 一张牌由「象牙牌身（`Front.svg`）+ 透明牌面」两层叠成——素材本身只有牌面图形，
  必须叠在牌身上才像实物；牌墙用同一牌身配绿色竹背板，避免原素材的红色牌背在牌桌上
  过于刺眼。
- 每家带座位卡：圆形头像位、相对座位名与座位号、庄家与行动中标记、桌内积分；
  财神徽章（财神×N）只在本家显示，因为官方快照不提供他家手牌，不能据此推断他家财神数。
- 牌面使用公有领域矢量麻将牌素材（`static/assets/tiles/`，来源与许可见
  [素材说明](static/assets/README.md)）：万/筒/条/字与牌背都是实物牌面，白板既是
  财神并在右上角加金色「财」标记；牌桌毛毡与座位头像同样走本地素材。
- 手牌按「万 → 筒 → 条 → 字（东南西北中发白）」排序展示，**刚摸的那张排在最后并
  单独留白高亮**；官方返回顺序只用于决策，不用于观战展示。
- 牌河与副露分区显示：牌河是朝中心的独立衬底区域（上下家每行 6 张、左右两家竖排
  两列），最近一张弃牌橙色发光，悬停可见第几张弃牌；副露每组带碰/吃/杠角标、
  独立边框，杠的末张竖放。
- 浏览器关页、刷新或切换场次会中断轮询连接；服务端把这类断开视为正常现象，
  不再打印 BrokenPipeError traceback，也不影响后续请求。

## 数据新鲜度

牌桌只使用两类完整事实：

1. 当前身份在动作窗口产生的完整玩家观察；
2. 官方 `state_response` 中的完整权威快照。

后续增量事件会立即列在“最新增量事件”中。若事件序号高于完整牌桌快照，页面会高亮提示，而不会凭不完整事件猜测四家牌河、副露或手牌。这保证 P0 的展示不会把推测误写成官方事实。

“有效牌 × 张数”是规则候选事实中的公开信息估计：以四张物理上限扣除本家手牌和已公开牌，不推测他家暗手或未来牌墙。

## 当前范围与安全限制

- 正式赛事和自由赛只显示该 Token 可见视角；不显示他家手牌。
- 官方快照不提供对手身份；座位按相对位置命名（本家/下家/对家/上家）并标注座位号，庄家带「庄」标记。
- 原始审计在队列压力下可能降级；页面会保留读取提示与快照/事件序号差，不承诺“全量牌谱”。
- 活动 JSONL 最后一行没有换行符时，观战器延后读取该行，直到写线程完成它。
- 服务端固定绑定回环地址，且页面有同源内容安全策略；不得用反向代理或端口转发暴露含本家手牌的页面。
