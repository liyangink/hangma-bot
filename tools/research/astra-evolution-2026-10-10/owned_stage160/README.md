# 完整阶段的有限进程监督

本目录公开已实际使用的阶段监督源码与必要回归。它直接拥有至多十个工作进程，调用原`stage160_budgeted.worker`完成原任务；控制器自身占第十一研究计算槽。算法、完整R16、同牌山、四真实座位和每窗原截止均由原驱动保持，监督器不按积分筛选任务。[研究与实际执行](../../../../doc/research/astra-evolution-20261010/WHITE-CIRCLE.md)记录范围与冻结摘要。

## 源码与验证

| 文件 | 用途 |
|---|---|
| `controller.py` | 拥有进程、原序派发、故障后停止新任务、自然排空，以及硬异常终止／等待／关闭 |
| `worker.py` | 在项目导入前绑定共同绝对截止，验原方法，再调用原单桌工作入口 |
| `harness.py` | 核单池声明及独立授权，保存任务、进度与资源；不自动开下一池或运行效果门 |
| `fake_tests.py` | 14项标准库检查，覆盖派发顺序、软停、故障、无法回收、启动未知及截止接线 |
| `spawn_smoke.py` | 真实进程的正常、失败排空和忽略终止后强制回收；仅睡眠／文件假任务 |

五份源码与已核冻结私有控制器逐字节相等。本目录未替换正在运行的私有入口，也不包含完整研究输入、候选包或运行结果。

内存回归不启动牌局或进程池，可直接执行：

```bash
.venv/bin/python tools/research/astra-evolution-2026-10-10/owned_stage160/fake_tests.py
```

真实进程回归须在资源已释放时执行，峰值为两个假工作进程加控制器，输出目录必须不存在：

```bash
.venv/bin/python tools/research/astra-evolution-2026-10-10/owned_stage160/spawn_smoke.py --out .private/owned-stage160-spawn-check
```

## 冻结运行入口

实际`harness.py`要求同目录的私有`DELIVERY.json`、完整阶段声明和独立根侧AUTH。这些文件绑定实际源码／方法摘要、已通过机械证据、候选和执行身份、十工作进程及零其他重进程；本目录源码本身不构成授权。重现时应先复制源码到新的私有冻结目录，核对并封闭对应来源，再生成单池授权，不直接复用历史绝对路径或旧批准。

```bash
.venv/bin/python <新私有冻结目录>/harness.py --declaration <冻结阶段声明> --auth <已核单池授权> --out <全新阶段目录>
```

所有截止使用本机单调时钟秒。整池7200秒从模块入口计，最后15秒仅供清理；工作进程沿用同一绝对截止，不按桌刷新。正常窗口预算仍由原经过时钟驱动提供，未计规则前序、网络与应用排队，不能授线上时限资格。

失败或停止标记只停止新派发，原在途任务继续自然退出；硬异常仅终止控制器自己拥有的进程。结果同时保留未派发、无返回、非零退出、强制清理与未知启动状态。只有全部原任务完整、所有进程已等待退出并关闭、来源未变且资源闭合，才能进入原阶段效果汇总。空闲解释器资源跟踪进程不计作策略工作进程，资源收据不冒称全机没有其他进程。
