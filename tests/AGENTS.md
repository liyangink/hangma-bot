# 测试实施规范

- 测试只通过模块公开接口验证行为，不依赖内部私有状态。
- `tests/contracts/` 固化跨模块类型、结果分类和安全不变量；接口变更必须先更新这里并经总体架构评审。
- `tests/fixtures/official/v8/` 保存已脱敏官方响应；不得放 Token 或 `Authorization`。
- 规则金例与官方 `fan-calc` 对拍结果必须记录来源、指南版本和抓取日期。
- 时间测试注入单调时钟，不使用真实长时间等待；并发测试证明四 Token 隔离、同用户M场共享state滚动总额度与state429冷却，同时保留每场连接槽及非state冷却隔离。验证任意滚动窗口不超过官方上限，并覆盖明确截止排序、未来边界保护及过期未发送请求不计次。
- 端到端基础接线先用假会话回归，受影响工程按需用官方测试房间验证。按用户2026-10-06修正，正式／测试赛事只验基础接线、配置绑定和生命周期，不要求参加官方现场作为上线门禁；以[现行验收口径](../review/vip-route-2026-09-30/evidence/t192-targeted-followup-1/ACCEPTANCE-POLICY.md)为准。
