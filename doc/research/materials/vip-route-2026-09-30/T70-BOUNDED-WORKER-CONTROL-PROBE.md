# T70：有限排队与过期结果门控诊断

**人工任务验证了计算队列可以设上限、旧结果可以丢弃、取消后工作仍有人收尾。尚未实现生产计算服务，也没有通过候选时限门。** 2026-10-02，T67固定1024桌长批仍在运行；本次没有读取其中途成绩，没有改候选、规则、接线或冻结文件。

## 本次做了什么

**以两个实际预热子进程测试25个控制请求，其中13个执行了人工工作。** 人工工作只是固定短等待或抛出异常，不是规则分析、构图或候选评分。未调用LLM、创建模拟完整状态或桌赛。调用方提供当前窗口事实，服务只核对场次、窗口、规划版本、权威序号、输入摘要和候选摘要，不自行产生权威状态。截止统一使用本机单调时钟秒，排队不延长原截止。

| 控制情景 | 实际结果 | 边界 |
| --- | --- | --- |
| 新旧窗口及序号／输入／候选身份变化 | 四个旧请求失效；新请求正常完成 | 已发的旧工作仍收尾，结果不用于新窗口 |
| 调用方取消在途工作 | 一次回执取消，工作结束后结果丢弃 | 没有把取消协程冒称为取消底层进程工作 |
| 待发工作取消或到期 | 取消一项、到期九项，均未派发 | 原截止不因队列等待重建 |
| 工作已发但迟到 | 一项在原截止返回到期，迟到结果丢弃 | 没有算作正常候选及时完成 |
| 工作异常 | 一项错误回执，异常已取回 | 不产生未认领的异步异常 |
| 十个场次同时登记，另来一个 | 最多两个在途、八个待发；第十一个立即拒绝 | 人工控制情景，不是真实官方十场接线验收 |
| 全部结束及关闭后请求 | 25个回执均终态，13项工作均收尾；关闭后不派发 | 子进程在有限人工工作完成后退出 |

六个工作结果被接收、六个迟到或失效结果被丢弃、一个异常被取回，合计13个真实派发。108次5毫秒计时控制的最大滞后约1.310毫秒；截止回执最大滞后约1.110毫秒。并发T67负载没有受控，不能据此声称线上P99或动作窗口已过。
