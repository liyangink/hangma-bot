# T45：公开领取证据的有界复用

**结论：只缓存同一不可变公共历史在同一官方水位下的解析证据。公开计数、牌张守恒、直接领取证据和本人未见容量仍逐次重算。** 现有公开计数回归及新增接缝测试共 86 项通过。在 T44 原公开输入的小计数测量中，16,146 次调用的耗时中位数从 1,020.10 毫秒降到 582.76 毫秒，减少 42.87%。这不是整个构图的耗时，也不是线上动作时限验收。

日期：2026-10-02。实施范围由根代理划定，只有 `public_tile_counts.py` 和新测试文件；没有修改公开签名、规则版本、策略、候选源码、执行器或历史证据，没有自行提交 Git。

## 1. 为什么可以复用

**条件分支会改变牌河、副露、手牌张数和墙余，但会共享同一份已经发生的公共历史。** T44 的权威剖析发现 `_claim_proofs` 对同一历史重复解析 16,146 次；在带剖析开销的那次运行中，其累计耗时为 1.217 秒，公开计数整体为 3.116 秒。不能把这些带剖析开销的数值当成正式运行时限。

领取历史解析的全部输入实际只有：公共历史原件和有效官方水位。有效水位是 `consumed_seq`，为空时取 `snapshot_seq`。解析后如何把证据对应到当前副露、是否仍然留河、直接证据是否冲突，仍由原公开计数逻辑负责。

这里没有新增任何杭麻规则假设。证据内容、缺口处理、同序号冲突、顺序回退、单局重置和被动事件判断均保留原逻辑。

## 2. 具体实现和边界

**键按完整 tuple 的身份比较，不散列每个事件，也不按手牌或牌河摘要猜测等价。** `_HistoryIdentity` 强持有历史原件，哈希使用对象编号；比较要求是同一个原 tuple。强引用使仍在缓存中的原件不能被回收，因此其对象编号不会被另一个历史原件复用。

| 条件 | 实现行为 |
| --- | --- |
| 同一个规范不可变历史原件、同一有效官方水位 | 复用不可变证据元组 |
| 内容相同但属于不同 tuple | 独立首次解析；没有靠内容猜测来源相同 |
| 同一 tuple、水位变化 | 独立缓存键，仍按新水位截取事件 |
| 历史追加、同序号冲突、乱序或单局重置 | 新原件重新解析，保留原冲突或清理结果 |
| 历史是可变容器，或其中含非规范/可变值 | 不纳入缓存，继续原解析路径 |
| 历史超过 4,096 条事件 | 不纳入缓存，继续原解析路径 |
| 当前副露、牌河、墙余、直接领取证据变化 | 不缓存对应计数，原有逐次对账照常执行 |
| 本人暗牌、单列摸牌、飘白次数变化 | 逐次重算未见容量；未知继续保持未知 |

首次纳入时，检查精确 `PublicEvent` 类型及其全部字段的深层不可变性，包含参与同序号相等比较的终局明细字段。只接受规范 `Tile`、精确字符串/整数/布尔、空值和递归不可变 tuple。子类带来的可变比较语义不进入缓存。命中后不重复检查整份历史。

**缓存管理有界并具有并发维护保护。** 使用 `functools.lru_cache(maxsize=8)`，最多持有八个“历史原件＋水位”条目，每份不超过 4,096 条事件；解析证据数量不超过历史事件数。该边界限制的是保留历史和证据的数量，不声称任意外部字符串的字节数恒定。并发首次填充可能重复做一次纯解析，但不会改变结果或突破缓存条目上限。

**每次返回全新的字典和证据列表。** 缓存中只有不可变键和元组。原计数函数仍可以过滤证据或 `pop(0)`，不会消费其他调用的证据。原解析返回 `defaultdict(list)` 时保留该行为；冲突导致的普通空字典也保持原类型语义。

## 5. 待根代理集成验收

**本子任务没有完成整个图或候选的准入。** 根代理需要核两个原公开窗口的全图和完整评分等价，以及不带剖析的整体时间。缓存首次验证和极短历史的成本也应纳入整体观测，不能只看缓存命中循环。

剩余公开计数计算仍包括牌河、副露 Counter、守恒和逐实例对账，这是当前必须保留的正确性工作。后续若继续优化，应先有剖析证据和公开 seam 对拍，再选择边界；不得通过复用旧未见容量或跳过守恒把性能做出来。
