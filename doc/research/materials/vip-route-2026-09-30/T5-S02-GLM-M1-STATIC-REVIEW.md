## 3. 容量与互斥路线没有重复兑现

当前规则投影给综合推进码的去重元组；每码在 `outletfacts` 只访问一次。精确正容量累加的是公开未见张数，含他家暗牌；精确零不计活宽，保守/未知证据用显式 1 张代理。`variety` 是参与统计的牌码种数，既含精确码也含非精确代理，不能称全部已核牌墙出口。源码从不除以墙余形成摸牌概率。

`backupcredit` 的 `anchorset` 排除所有综合码，故同码不同时进入普通出口库存项和备用自然推进库存项。目标自己的 `conditional_need_improvement_codes` 由当前自然结构规则按规范牌序去重并排白；变量 `width` 实际是该目标独有码的**公开容量/代理和**，不是牌码宽度。多个白用途或两种牌型可能共有这些码，但逐用途 `proposal` 最后只取最大，不把共享库存或互斥路线支付相加。

条件支付表已由当前数据传输对象（`DTO`，将规则冻结事实送给评分代码的只读映射）保证规范码顺序、同码至多两种抓打假设、键唯一、同码容量一致且为 1—4。`envelopepay` 只在换码及最终一码结尾累计一次容量权重；同码内部更新低/高值，未重复累计实体容量。两个抓打假设也未当成两次成功机会。高包络 `envhigh` 只写入 `parts.ehi`，没有进入 `gain`、`cond` 或最终排序。

普通速度、条件支付与最大备用形态仍是联合排序中的不同启发式分项；这种相加没有重新授予合法性或声称能同时兑现多条路线。`replacement` 码数奖励也仅构成下端到上端之间的有界排序代理，而不是多次补摸的积分和。

## 4. 当前胡同尺度与严格升级门

当前胡和条件行都取 `score_delta[seat]/base` 后调用同一单调 `30*x/(60+abs(x))`；现在胡节点为 `10+paypoints(x)`。低包络均值是已知局部见证行的组成支持，未解释成墙内分布或真实长程积分。

对 `wait`/`unknown_draw`，只有 `envlow>anchorpay` 才产生 `gain`。若低包络不高于当前胡，`gain=0`，且当前真实等待态向听不小于 0、未知补摸扣分不小于 0，故有：

```text
等待评分 - 当前胡评分
= gain - riskcost + spec - 0.8*shanten - undcount
<= 0 - 1.7 + 1.0 - 0 - 0 = -0.7
```

未知补摸另扣 2.6，故无升级时最多低当前胡 3.3 点。真实投影明确拒绝已胡 `-1` 的等待态；这个边界不是对任意手工伪造 DTO 的证明。新增未知奖励没有单独突破 1 点总投机预算，也没有凭未知资格推高已知支付包络。因此同价、未知或没有已分析支付的等待节点不能仅靠速度/未知奖励压过当前胡。

**风险 R01：升级门采用低包络平均及全部已见证胡码宽，不能解释成每码都已升级。**`huwidth=len(legal_hu_draw_codes)` 不是严格高于当前胡的牌码并集；平均超过当前胡可同时含较低、同价和较高支付码。未知码没有进入支付平均，但有限投机奖励仍可影响已存在升级的边缘排序。低包络也可能在实际自由抓打条件下过于保守。需要自有机会证据核查有利升级是否仍能兑现，不能从此公式宣布增强。

这个严格等待门没有改写图内未来 `hu` 节点：给定条件后的合法胡仍直接使用同一支付变换，再由 `replacement`/`condition` 聚合。这部分从父代保留，完整图没有给每个未来结算统一扣 `riskcost`。因此不能把上面的等待节点不等式推广为所有非胡根都必须严格高于当前支付才可选择；若要主张全图严格兑现门，须由真实图及结算支持另核查。

## 5. 未知与 None 边界

实际评分路径没有把未知资格写成已知零支付行。七对 `None` 先被保护；`legal_hu_draw_codes` 的长度只在存在已知非空支付包络、符合 DTO 表一致性时读取。支付未分析 `None`、已分析空表 `()`、部分未知仍由输入区分，未知码仅作明确的有限启发式奖励，不加入同码支付组或库存权重分母。

`envlow/envhigh` 的内部默认值为 0，但 `envelopepay` 只在 `drawopen and payments` 时调用；未分析/空表不能产生真实支付增益。无当前胡时，支付条件项也只在非空表使用；部分未知的有限补项另由 `payments is not None` 保护。缺墙余并没有将未来普通摸资格伪装成已确认：当前框架的必需墙余缺口在构图时拒绝，未知补摸仍留在自己的代理节点。

**风险 R02：新增低/高包络解释丢失未知状态。**S02 第 158—161、179、196 行在未分析、空表或 `drawopen=False` 时都会输出 `elo/ehi=0`，解释没有 `payment_state` 或同等状态字段。该 0 在代码中是“支付项未使用”的占位，并非已证实零支付；读单条 trace 无法还原三种情形。评分本身有真值保护，故本审核不把它判成新增零支付决策缺陷；后续审计须绑定完整 DTO，不能把该解释值统计为未知码的实际支付。

另有父代保留边界：`evidence==exact` 但容量为 `None` 时不会给普通或备用库存支持。当前兼容码/资格投影仍保留此码并把其资格列为未知，不因此删除合法根；不能把该缺支持解读为已证耗尽。保守/未知证据即便容量下界为 0，仍贡献代理并保留相容性。

## 6. 完整图、有限输出与资源

完整图按子节点在前处理。`choices` 比较全部子节点；`replacement` 使用全部相容补牌子节点的最小/最大值，并在 `[lower,upper]` 内加入最多每改善码 0.06 的有限代理；`condition` 为 `lower+0.2*(upper-lower)`，仍在互斥包络两端之间。它们都没有把最高补牌当必然，没有将不同条件声明为同时发生。`unknown_draw` 保留真实补牌前结构并扣 2.6，不用零分或最佳补牌替换。

源码保留空聚合节点的 `GAPVALUE=5` 占位，但当前严格骨架在调用候选前拒绝任何 `gap_kind`，完整聚合节点必须非空。因此该分支不能作为正常研究缺图的成功补分。最终按全部输入根逐项写输出；没有按动作族、当前胡或已知/未知过滤根，契约验证仍拒绝重复、漏项、越界和非有限输出。

合法生成事实域内，分母 `60+abs(amount)`、`14+anchorsum`、`variety+4`、`huwidth+3`、`3+variety`、三项公开风险因子及 `25-20=5` 都严格为正。支付均值在正 `weightsum` 内除法；非空真实支付表有精确正容量。`BaseScore` 是正整数。常量未变，没有新增负分母、可空直接运算、无界范围、递归、指数幂或嵌套维度；自然目标至多十项，各目标自然码至多 33 个，综合码至多 34 个，支付至多 68 行。
