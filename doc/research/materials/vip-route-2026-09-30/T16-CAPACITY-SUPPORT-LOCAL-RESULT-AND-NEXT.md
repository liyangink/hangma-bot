# T16：局部容量补足有正例，下一步检查公开交互取舍

**2026-10-02，目标 active。** T16 已完成旧128公开窗、旧局部10条续打、新自然16完整桌、新32公开窗及新实际路径20条归因。旧局部确有一次动作增益；新自然完整桌仍负，且找到首动作造成损失的反例，不能晋升。下一批只派一份 T17 作者，研究已有公开信息的交互取舍。本批新增独立交叉评审 **0**，常规核验由根代理完成。

## 改了什么

**只让现有公式利用正的保守容量下界，没有换规则、另加常数或指定某张牌必打。** 原父代对非精确容量统一使用 `0.8` 排序代理。T16 在无当前合法胡、本人仍持白、普通摸牌空间尚开放且等待叶仍持白时，对逐码的正保守下界补足 `max(0, 下界−0.8)`，再进入父代原饱和支持式。同码只计一次。

保守下界（`ConservativeCapacity`，公开记录不够精确时仍能保证的未见张数）包含他家暗牌，并非牌墙内张数或摸到概率。零和未知继续未知；精确张数、合法胡资格、结算及自然目标均沿用父代。规则依据是现有[公开计牌模块](../../src/hangma_bot/hangma/public_tile_counts.py)，未复制另一套麻将数学。[作者原答与静态说明](./evidence/t16-conservative-lower-support-author-1/STATIC-CHECKS.json)

实际作者委派 1 次，请求 GPT 6.1 Sol max；后端实际模型和 token 未暴露。正式回灌没有新作者调用，原答不改写。包装中的 `finish_reason=stop` 是根根据已交付文件和子代理终答作的完成声明，不冒称供应商 API 返回。[原答首封](./evidence/t16-conservative-lower-support-author-1/ROOT-AUTHOR-REPLY-FIRST-SEAL.json)、[装载前检查](./evidence/t16-conservative-lower-support-author-1/ROOT-LOAD-PREFLIGHT.json)

[嵌套续打闭合](./evidence/t16-nested-first-difference-closure-1/ROOT-CLOSED-CHECK.json)从 T15 原隐藏样本恢复25次已记录推进，逐帧核完整玩家观察、窗口及合法动作，定位到同一个 seq607。不是新增自然母根，也不是重建历史持牌后验。此时 R18 和 T16 都弃7饼，真父弃9饼。

## 下一步只改一个机制

**T17只研究公开弃牌交互取舍，不再同时叠新的容量、支付和自然先验。** 一份已授权Sol max作者从真正T16同额度包出发，输出完整联合公式。作者获得旧局部正例、新首动作反例及两处尚未知效果的公开分歧，禁止按牌码/seq/历史题写答案，禁止把粗代理写成真实概率。当前Hu与当前零白的所有动作数值保持父代。[作者START](./evidence/t17-public-interruption-trade-author-1/ROOT-AUTHOR-START.json)、[具体任务](./evidence/t17-public-interruption-trade-author-1/AUTHOR-TASK.txt)

这是基于反例选择的工程研究方向，尚未证明公开交互缺失是主要损失原因，也未证明某套公开代理优于单看自己路线。新公式若不改有效行为、或续打没有收益，按本批边界停止同类扩量，不把这次方向选择写成已确定的修复。

先正式装载并做同合同公开探针；有实际、可解释的改选才复用小型归因工具。后续自然开发先冻结4个未曝光seed、H/M与四换座共≤64实例，但尚未START，不能当成已打样本。根根据反例、普通出口和高番取舍决定是否消费预算；没有信号不自动追加作者或大桌赛。[执行计划](./evidence/t17-public-interruption-trade-author-1/EVALUATION-PLAN.json)

当前胡、零白护栏只是本提案范围；保白、高番和未来竞争估值仍有未验证部分。正式确认另取未曝光来源，规则、动作时限、接线与赛事门均保持。既有线上R18未修改。

**评审节奏已收缩。** 同工具常规实验只做一次根核身份、分母、失败、算术和真实输入；规则/受控接口改变、首次关键工具与拟晋升集中独立评审。原始失败与成本保留，阶段性提交推送；不以重复审核增加“算法证据”。
