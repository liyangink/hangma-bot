## 2. 结构事实

**自然牌缺口（`NaturalTileNeed`，指定用途与目标下理想条件中至少还需补的自然牌张数）不是实际向听或摸牌概率。**唯一数学实现在 `hangma`；真实普通型／七对向听不改。

入口 `analyze_route_structure(counts34, meld_set_count) -> RouteStructureFacts` 返回不可变事实，接受 `sum(natural_counts33)+whites_held=13-3*meld_set_count` 的等待手牌。杠折算一个面子，实体第四张仍在公开库存。多一张行动态先沿同源规则展开合法动作，不能虚构第十五张。此入口不读网络、文件、时钟或完整世界。

| 事实 | 单位与边界 |
| --- | --- |
| 自然计数／对子／四张 | 33 维自然牌计数；四张算两对；保留规范牌码 |
| 牌型、保白量 `k`、块内用白量 | `k=0..w`；块内恰用 `w-k`，独立枚举核验；不预先绑定某孤张 |
| 目标阶段 | `complete_structure` 为剩余面子＋将或七对；`waiting_predecessor` 为剩余面子或六对＋一白，七对要求无副露 |
| 自然缺口 `D` | 指定目标所需自然牌向量相对实持牌的最小正缺口和；前驱自然目标大小 `12-3m-(w-k)`，故 `D>=k-1` |
| 条件动作数量 | 前驱补 `D` 自然、弃 `D-(k-1)` 自然和 `k-1` 白；完成目标自然弃下界 `D-1` |
| 必需终点摸牌 | 前驱 `D=0` 仍需合法摸牌／补牌才可能胡，不与完成目标直接比较成胡速度 |
| 条件缺口推进牌码 | 固定用途补一自然牌使缺口下降；不是合法续行或高番资格证明 |
| 见证与范围 | 无分解见证明确 `distance_only`、见证为空，不填虚构结构 |

补张下界仅对指定自然补张路径成立；新增白板、吃碰、杠另开转换，不作为所有胡路线的全局下界。精确用途求解必须核验物理每码四张与数量守恒。

实际进张分别保存**结构推进集合**和**直接合法胡集合**。后者由给定摸牌后的同源规则判断，不强制再弃；前驱 `D=0` 不意味着胡宽度为零。并集按牌码去重并保留交集与用途。换目标本身不能伪装为同目标进展。

公开容量从真实全手与公开事实计算，包含他家暗牌。精确零可证耗尽；保守下界零／未知不能删相容码，也不能除以墙余冒充概率。

## 2.1 自然面子准备：不假借未来白板

**自然面子准备（`NaturalSetPreparationFacts`，真实手牌不用白板百搭、只凑剩余自然面子的程度）单独表示“白板以后是否有机会留给大牌”。**入口 `analyze_natural_set_preparation(counts34, meld_set_count)` 复用唯一标准型目标距离求解器。输入仍为真实 `13-3m` 等待态。目标恰有 `4-m` 个自然面子，不含将，不借现有或未来白板；白库存原样保留。

| 字段 | 含义与边界 |
| --- | --- |
| `natural_counts33`、`whites_held`、`meld_set_count` | 与同一等待态真实结构严格相同；规范牌序和实体库存不变 |
| `sets_left`、`target_natural_size` | 剩余自然面子组数及实体张数，分别为 `4-m`、`3*(4-m)` |
| `natural_draw_lower_bound` | 同目标缺张 `D=min sum(max(target-current,0))`，单位张，不是等候摸牌次数 |
| `natural_discard_lower_bound` | 达到该目标所需自然弃牌下界 `sum(natural)+D-target_natural_size`，单位张 |
| `natural_need_improvement_codes` | 补一张自然牌使同目标D下降的规范码，不证明牌山有该码 |
| `target_distance_evaluation_count` | 该结果构造所需距离请求量；不是缓存命中时新增实际后端执行次数 |
| 外层 `natural_preparation_code_width` | 改善码中与当前公开容量相容的码数；精确零关闭、保守或未知零保留 |

`D=0`只说明已有所需自然面子，不说明有白、已爆头、已胡或将来必摸到白。该事实不能代替真实向听、七对目标、合法资格或条件支付。七对的自然准备继续沿原目标事实；本次不新增第二套七对数学。

新事实挂在 `RouteWaitingView.natural_preparation`，覆盖所有已形成的真实等待态，包括未知补牌前态。视图及图均升为 `/3`；自然准备语义为 `vip-natural-set-preparation/1`，已有支付语义 `/1`不变，候选种类仍为 `vip_route_heuristic_v1`。附录提供全部真实字段，模型只进化联合权衡公式。

## 3. 全动作与条件见证

**全部当前合法动作参与排名；未来条件声明范围。**吃碰保留全部合法弃牌及未摸时合法暗／补杠，获裁决后重评真实观察。杠补按相容牌码展开，不挑最好补牌当必然，不因未知删杠。正常机械缺实现、必需输入缺证据、未来未知、深度外和工作量截断分开。

`analyze_waiting_draw_witness` 为合法弃后等待态提供局部条件见证，显式指定墙余、抓打限制和下一本人摸牌，标记 `local_witness_only`。它不证明能活到该摸牌，不是完整公开事件链或 P2 门证据。未裁决结构分支须先给定完整裁决条件，不得直接提升为已发生状态。未知资格可作为未知事实交候选；当前动作或必需输入无法正确形成时研究桌未完成。

仅查询胡资格时可用同源窄入口 `analyze_waiting_hu_witness`：只返回合法胡、即时结算、问题及被摸牌码的容量变化，不返回未计算的向听、进张或完整后态。内部 `HandWinEvidence` 由同一成胡数学产出；动作门禁、爆头及结算仍复用唯一规则实现。优化必须与完整见证逐项对照，不靠删除根或续行提速。

他座终局内部字段 `other_draw_replacement: bool | None` 区分已给定普通摸（False）、补摸（True）、未摸／来源已消费（None）。`expected_discard_seat` 不能证明他座刚摸牌，吃碰未摸暂态不能接受自摸终局。该字段不扩展官方观察或事件。

## 3.1 条件胡支付：保留已有规则结果

**候选需要同时看到“现在胡能得多少”与“给定下一次本人普通摸牌后，立即胡能得多少”。**条件胡支付（`RouteConditionalHuPayment`）复用已有窄见证的结算，不新增成胡算法或见证查询，不评估途中存活率，不是长期精确期望积分。经典开发观察中当前胡为96分，合法弃牌后的条件支付为自然牌192分、白板384分；这说明存在值得权衡的条件优势，不证明继续必然更好。

`RouteWaitingView.normal_draw_hu_payments` 保存以下冻结表；等待节点本身 `settlement` 仍为 `None`，当前合法胡节点仍保存即时 `Settlement`。

| 字段 | 单位、来源与约束 |
| --- | --- |
| `draw_code`、`catch_restricted` | 下一本人普通摸牌的规范牌码与抓打限制假设；同码两假设互斥，不能当两次机会相加 |
| `wall_remaining_before_draw`、`wall_remaining_after_draw` | 本局部条件摸前／摸后墙余，单位张；摸前须大于20，摸后仅扣本人这一张，不推进其他座位 |
| `draw_capacity_before`、`draw_capacity_after` | 同码精确公开未见张数，摸前1—4，摸后减一；包含他家暗牌，不是墙内数量或摸牌概率 |
| `baotou_after_draw` | 唯一规则源算出的给定普通摸牌后爆头资格 |
| `chain_count`、`chain_piao` | 当前条件等待态已有链数、已飘白数；证据不足不能填0，也不预测途中新增飘／杠 |
| `winner_seat`、`dealer_seat`、`ruleset_version` | 本家／庄家座位0—3及本地规则身份，须绑定外层视图 |
| `settlement` | 条件成立且立即合法自摸时的同源结算：正整数番数、明细、座位0—3四维整数净积分，和为0；分数单位为积分 |
| `draw_kind`、`local_witness_only`、`scope` | 固定为 `normal`、`True`、`local_given_normal_draw_hu_only`，不扩大见证范围 |

表按规范牌码、`catch_restricted=False/True`排序，键不重复，最多68行。行对应的限制／自由抓打胡码分别严格等于旧两包络集合，牌码并集等于 `legal_hu_draw_codes`；容量须与等待态同码的精确正容量相同，不能产生实体第五张。每行链状态、墙余、座位和规则身份须一致。可审计的构造错误直接拒绝，不吞成未知或0分。

未分析时表为 `None`，须与未分析胡资格及其原因一致；已分析无合法胡时为 `()`。部分资格未知时只保存已有精确合法支付行，未知码留在 `qualification_unknown_codes`；未知码不是0分或已排除。缺失必需链或计分证据继续按原严格失败处理。

这是“给定本人下一次普通摸牌”的局部条件。它没有承诺其他三家会放过本动作、途中不会先胡、本人会再次摸牌、所需码位于牌墙或之后继续动作的链资格。墙余只是局部摸前条件；近保留区观察尤其不能把条件行理解为真实未来必达。杠补与更远成型路线仍按各自原节点范围处理。

视图版本 `vip-route-scoring-view/3`、图版本 `vip-route-action-graph/3`、支付语义版本 `vip-normal-draw-hu-payment/1`。候选架构类型仍为 `vip_route_heuristic_v1`，自然结构数学语义不变，评分审计轨迹仍为 `/1`。新合同 SHA、版本、完整依赖闭包、规则／额度和源码形成新身份；旧 v1 成绩不得直接迁移，旧包不得作为当前兼容父代装载。旧源码可明示作历史参考，当前人工种子和模型提案必须重新建立、实际评测。

## 4. 评分与严格执行

**只开放一套联合排名代码。**候选类型 `vip_route_heuristic_v1`，视图 `vip-route-scoring-view/3`，入口 `score_actions(view) -> ScoreBatch`。旧 `/4` 输入合同不变。新冻结类型 `VipRouteScoringView` 以有界图描述根与续行，子节点先于父节点；根表与同次合法候选对应，各节点说明阶段、条件、用途与覆盖，不预选最小向听分支。

每个输入动作键恰一条有限评分与有界解释。评分点越大越优，不是实际积分，不跨候选比较绝对量级。当前胡真实支付作为有单位的事实经候选变换参与取舍，框架不得直接混加任意代理分。

执行器新增精确类型入口 `score_vip_route`，复用静态检查、工作量、完整输出及跨调用状态守卫；旧 `score(ScoringView)` 不改。严格研究包装对异常、弃权、超量、非法和漏项显式失败，不能复用生产内部紧急降级。完整评分首选恰与紧急候选同键不是回退，未获得完整评分而走保底才是研究失败。

起始候选额度 100,000 计数操作、4,096 局部集合项、32 KiB 解释；规则建图另声明节点／分支／深度限额。全部计算计入实测决策耗时。逻辑时钟不能证明官方1秒／3秒可部署；有价值但慢的机制可另冻有界研究额度，最终部署版本仍须实机验收。

## 4.1 共享图与实际执行容量

**只复用整个冻结节点事实，合法根和所有边保持完整。**相同节点允许多个父引用；比较包含种类、全部有序子引用、条件牌码、等待事实、结算、未发生条件、未知说明、合法动作及跟打身份。边的顺序和重复引用不得去掉。`node_key`是引用名称，存储节点数不是独立机会数量。工作量统计以实际存储节点／边为准，资格查询和距离计数另列。

新VIP执行器单集合容量由冻结 `projection_limits.max_nodes` 导出，并在身份参数及模型附录中显式保存。默认仍4096，可信配置最大16384；旧评分执行器默认不放宽。研究可另冻8192节点、16384边、65536资格见证及240万操作的配置；这不是默认值更改，也不是线上时限证明。共享及新事实会改变输入身份，任意旧公式仍须重新实测，不能自动继承旧成绩。

**海选专用候选接受一定普通效率损失，重点检验长批次实际总净积分。**用户提供“过半弱Bot”作为主场景事实；具体弱对手比例和行为版本事前冻结，强对手诊断单列。提高联合公式的大牌保留权重，不人为放大官方结算。执行规模、失败分母和停止规则见[海选追大取舍](./QUALIFIER-HIGHFAN-TRADEOFF-2026-10-02.md)；旧冻结批次不回填新口径。
