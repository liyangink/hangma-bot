# VIP P2 机械闭包独立交叉审查

日期：2026-09-30。审查对象是当前未提交的 `route_transition.py`、`route_frontier.py`、P2 机械矩阵及生产规则路径；不修改生产代码。依据为 [研究证据索引](../INDEX.md)、[Astra 实施方案](../NEXT-GENERATION-ROUTE-HEURISTIC-IMPLEMENTATION-ASTRA-2026-09-30.md)、[官方指南 v34 正文快照](../../doc/references/official-guide-v34-content.txt)（2026-09-15 抓取）与生产 `action_families`、`candidate_facts`、`value_analysis`、`progression`、`engine`。v35 全文尚未核验。本审查判断当前实现与设计，不签发 P2 机械完成门。

## 结论

**P2 门未通过，且现有条件状态尚不足以构成正常动作的闭合转移。**根登记和若干指定动作组合是有用的局部量具；即使全部现有单测通过，也不能将其解释为每类正常动作及给定公开事件已有完整合法性、资格、番数和物理可达性。下表严重性为：S1 阻断 P2 门或会产生错误规则状态；S2 影响完整性及审计可信度；S3 改善证据质量。

| 级别 | 发现与可核对反例 | 最小修复及验收 |
| --- | --- | --- |
| **S1** | **弃白后的圈主状态错误。** `route_transition.py` 的弃牌根仍经 `_state` 原样拷贝 `context.catch_play`（约 179—185、128—135 行）。官方 v34 §1.1 规定任意弃白重开抓打圈，弃白者本人豁免。用 `catch_play=True`、圈主为座位 1、本人座位 0 刚摸白的完整窗口投影，唯一合法根 `discard:白` 的后态却是 `catch_restricted=True`；本次小反例实际输出 `[('discard:白', True)]`。这不是未来裁决未知：本人动作已确定地换主。 | 条件状态携带圈是否活跃、圈主座位或相容圈主集合及证据；弃白、原圈主弃非白按 `progression`/`catch_play` 同源规则转移。至少增加“非圈主被迫摸切白→本人成圈主”“圈主弃非白→关圈”“他家再弃白→换主”的正反例，并逐步比较合法候选。只有布尔 `catch_restricted` 不能维持后续事件。 |
| **S1** | **公开四张守恒丢失，会接纳物理不可能的条件摸牌。** `ConditionalRouteState` 只保存 `meld_count`，`apply_given_draw` 仅检查本人暗牌同码是否已有四张（约 38—52、314—315 行）。例如刚补杠 `1w` 后，本人公开副露已有四张 `1w`，暗牌无 `1w`；给定下一补牌 `1w` 仍被接受。用该类待补状态调用，实际返回 `drawn_tile=1w, wall_remaining=59`。公开牌河与他家副露的同类四张也会被忽略。 | 保存具体本人及四座公开副露、牌河、重叠/供牌证据；复用 `public_tile_counts` 枚举**正公开未见容量**牌码。容量零拒绝该给定摸牌，容量未知返回输入证据缺口而非擅自接受或填零。补杠自身四张、他家公开四张、牌河与被鸣牌重叠三类要有金例。 |
| **S1** | **响应后的正常事件算子尚不存在。** 过、弃、吃碰后弃均停在 `RESPONSE_RESOLUTION`；`given_next_normal_draw` 直接接收任意墙余和抓打布尔值（约 171—242、331—353 行），没有响应成员、碰窗→吃窗裁决、他家动作、流局、抓打圈主变化、公开计数或事件次序。给定这些公开事件后的下一合法状态本应由规则计算；未来事件是什么未知，**给定后仍不会算是工程缺口**。P2 矩阵对此已有正确的“未闭”标记。 | 先定义带真实来源和顺序的 `GivenEvent`；接入给定响应裁决与公开推进，拒绝跳过必经裁决的前缀。可不生成官方 `seq`，但须记录原权威水位与假设事件次序。按过牌、弃牌、吃碰生效/落空、无人响应、下一摸/流局逐格验证。 |
| **S2** | **吃碰后的暂态内部字段彼此矛盾。** `claim_state.meld_count` 加一，但 `_state` 沿用鸣牌前 `my_chi_count` 和 `my_peng_codes`（约 201—206、128—135 行）；只有最终弃牌分支才补上字段（约 228—235 行）。若后续把 `CLAIM_DISCARD` 送同源动作族，第二摊吃之后仍看似只吃一摊；新碰牌也不在可补杠牌码中。当前恰好没有该调用，不能据此算闭包。 | 在鸣牌生效的同一原子转移更新具体副露、吃摊数、碰牌码。测试从已有一摊吃再吃第二摊，断言 `claim_state.my_chi_count==2` 且下一响应无第三吃；碰后断言新碰牌在暂态副露，未来摸第四张后可补杠。与生产 `action_families` 对照，不能只比较分支键。 |
| **S2** | **机械故障和输入缺口分类仍需双轴保留。** `project_legal_roots` 为每个根追加 `observation_issues`；当前约 282—296 行虽已保护“无状态的机械故障”，但有分支的机械未闭根会被覆盖成 `INPUT_EVIDENCE_GAP`。例如正常弃牌根因响应裁决未接而标 `MECHANICAL_GAP`，只要观察附带独立缺项，就被改标输入缺口；单一 `gap_kind` 不能表达两者同时存在，逐格机械错误数会被低估。 | 分别记录 `mechanical_gap` 与 `input_evidence_gap`（或故障集合），统计机械错误不得由输入缺项清零。测试给正常弃牌根附加一个无关 `observation_issues`，要求响应算子未接仍计机械缺口。真正缺 `chain_piao`、`gang_draw`、圈主证据或公开重叠证据才计输入缺口；已知合法候选与移牌冲突计工程缺口。 |
| **S2** | **给定摸牌分析只产动作族，未产完整资格事实。** `analyze_given_self_draw` 复用 `action_families`、`hand_analysis` 和 `settlement`（约 373—398 行），对单次胡/弃/再杠有价值；但不附 `CandidateFacts`、公开容量、后续分支、根覆盖，也没有统一的故障类别输出。`GivenDrawAnalysis.issues` 为空仅表示这些调用未报错，不表示后继全部条件边闭合。 | 对给定动作重新使用规则主入口同源的合法候选、公开计数、价值资格与完整性语义；每根记录声明范围、未见牌容量及失败类别。先让胡/弃/三类杠在指定事件下逐根对账，再扩到全正容量牌码。 |
| **S3** | **现有测试主要是同源自对拍和伪观察。** `test_route_transition.py` 的 `_observation` 将 `last_discard` 设为序号 10，但四家 `discards` 与 `public_history` 仍为空（约 28—42、73—105、243—245 行）；吃碰后价值见证来自同一生产 `value_analysis`，不是独立自然轨迹或官方金例。暗杠测试仅核对若干牌码及相同规则函数。21 项 `route_transition`/`route_frontier` 定向测试通过，只说明局部一致。 | 构造牌河、副露、历史与最后弃牌守恒的完整观察；以冻结的官方可见自然轨迹作结果盲验证。保留同源单测作回归，再增加规则边界金例、候选全集与四座结算逐步对拍；记录观察来源、规则/配置摘要和逐格分母。 |

## 受控接口判断

**跨 `hangma` 与策略/离线评估消费时需要受控入口；内部试验量具暂不必先扩大对外契约。** 当前 `project_legal_roots` 接收外部传入的 `context` 与 `candidates`，docstring 要求“同一观察”，但函数只检查动作键重复，并没有证明二者与 `observation`、`config`、规则源码同源。正式 P2 前沿若依赖这个入口，可把旧窗口候选或错配规则配置装配成看似有效的根。建议由 `HangmaRules` 以一次观察、绑定配置和规则版本内部生成上下文/候选，输出显式命名的条件状态与逐根证明，不伪造 `PlayerObservation`。冻结跨模块输入/输出时，同步 `interface.py`、`engine.py`、`doc/implementation/interface-contracts.md`、`doc/architecture.md`、主技术方案、术语表、调用方与契约测试；纯内部原型不需要为未确定的大型通用状态提前签署接口。

## 最小可执行补齐顺序

1. **先冻结可守恒的条件状态。** 保存本人暗牌和具体公开副露、四座牌河及去重证据、本人/庄家座位、牌墙余量、抓打圈主及来源、爆头、链/链内飘白、摸牌来源、窗口/响应成员、规则配置/源码身份。空值保留“确实缺证据”；条件事件与官方已见事件分开，禁止制造官方序号。用状态不变量拒绝第五张、负墙余、错误副露张数和不合法摸牌来源。
2. **完成单步动作和给定公开事件裁决。** 从生产 `progression`、`action_families` 抽取/复用规则转移：弃牌及抓打圈，过牌及碰窗→吃窗，吃碰生效后未摸弃牌，明/暗/补杠与补牌，胡/流局。每步重算公开容量与资格。未知裁决保留条件分支；给定裁决后不能再报“未来未知”。
3. **逐格扩展组合与边界。** 全部正容量牌码的普通摸/补牌；连续杠、飘/断链、爆头进出、圈主换位、最后可摸机会；普通型/七对/豪华/四白交互。逐根报告登记率、结构完成率、资格完成率及正常机械格完成率。任何正常完整输入仍报机械缺口，P2 门保持关闭。
4. **独立复核后再交策略。** 用守恒的官方观察/自然轨迹盲验动作全集、资格、番数和四座结算；测试房核验协议事实边界。当前同源局部对拍只作调试。完成受控接口及契约测试后，才让独立策略在每个正常窗口持续决策并按 VIP 评测合同评价；局部机械通过不能被写成 `C_alg` 强度效果或可部署门通过。
