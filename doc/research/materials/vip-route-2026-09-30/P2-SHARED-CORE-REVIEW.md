# P2 共用规则底座独立审查

日期：2026-09-30。范围为工作树相对 `main` 的 `public_tile_counts.py`、`progression.py` 改动及 `test_conditional_public_counts.py`、`test_conditional_resolution.py`。本审查只读取代码并执行本地定向用例，没有调用官方服务或改动正式代码。规则依据为[官方指南 v34 正文快照](../../doc/references/official-guide-v34-content.txt)（2026-09-15 抓取）和[规则证据表](../../src/hangma_bot/hangma/RULES_EVIDENCE.md)；v35 尚无全文，故以下反例是条件输入的物理一致性审查，不声称已在官方运行中出现。

## 结论

公开牌条件入口存在两项确定的计数缺陷，均会把尚不能精确判断的牌码标成 `exact`。P2 的物理容量门不宜凭当前新增用例判定通过。公开响应裁决与抓打圈转移在本次检查范围内未发现可复现的优先级或圈主错误；这个结论只覆盖下述静态分支和定向测试，并非官方测试赛事验证。

## 发现

1. **高：四张分布在副露时，非领取牌也被算作可解释河牌，明确的第五张被掩盖。** [`public_tile_counts.py` 第 385–405 行](../../src/hangma_bot/hangma/public_tile_counts.py)的 `possible_claims` 对所有包含目标牌码的吃副露加一，不检查该吃实际领取的是哪张。只要可能领取次数不少于河中张数，就直接返回 `(4, exact)`。最小条件反例：座 1 吃 `(1w,2w,3w)`、明确领取 `2w`；座 2 碰三张 `1w`、供牌座 0 且座 0 河中无 `1w`；座 3 河中另有一张 `1w`。四张 `1w` 已在两个副露，座 3 河中这张必为第五张，然而函数给 `1w` 返回 `4, exact`。此时应为未知/输入冲突，不能把条件状态当成物理可行。现有测试只覆盖单个四张杠与河牌，未覆盖“吃一张 + 碰三张”的跨副露组合。

2. **中：混合留河/移河条件分支把旧同码弃牌误作本次领取牌。** [`public_tile_counts.py` 第 250–266、337–348 行](../../src/hangma_bot/hangma/public_tile_counts.py)的 `_claim_vote` 只看供牌者河中是否仍有同码牌；`PublicClaimEvidence` 只保存供牌座位与牌码，不保存本次被领弃牌是否留河。条件推进接收逐次 `retained_in_river` 并修改河，但写入证据时丢弃该事实。可构造一个张数守恒、物理上可行的分支：座 0 河中有旧 `1w`；其后座 1 碰座 0 新弃的 `1w`，该新弃牌移河；另一次座 2 碰座 0 的 `2w`，这次被领牌留河。两个碰副露分别为三张 `1w`、三张 `2w`，座 0 当前河为旧 `1w` 与留河 `2w`，公开张数守恒差为 1。`_claim_vote` 因旧 `1w` 仍在河中而错误地再扣一次，返回 `1w` 的 `(3, exact)`，真实公开张数为 4。这会虚增该牌的未见容量。应保存每次领取牌的留河身份，或在同码旧弃牌无法辨别时标为非精确，不能用“河里有同码”证明同一物理牌重叠。此反例是条件口径混合情形，不等于声称官方某个快照曾混合两种口径。

两项反例均以 `.venv/bin/python` 直接构造 `PublicTileView`、`PublicClaimEvidence` 并调用 `count_public_tiles_from_view` 复现，输出分别为 `four-meld-with-fifth-river 4 exact` 与 `mixed-retention-claimed-removed-but-same-code-older-river 3 exact`。第 1 项对应输入冲突；第 2 项对应守恒成立但本次领取身份不可由牌码推出。修复时宜为两项各补一个逐牌码测试，并核对 `public`、`unseen` 与 `evidence` 三向量。

## 已覆盖与局限

- 新增公开牌与响应测试 27 例、既有公开牌/推进/抓打圈/事件载荷测试 87 例，合计 114 例本地通过。旧观察入口的公开与未见张数仍走共用核心的兼容参数；既有测试未显示旧入口回归，但没有对所有 34 牌码及所有历史快照作穷尽对拍。
- 响应核心检查了碰/明杠先于吃、全过后开启下家吃窗、未齐选择停留、两家碰/明杠保持 `blocked`、圈主接力及圈内响应身份；代码复用到模拟器的碰窗和吃窗。未获得新的官方同时响应裁决样本，不把本地条件组合升级为官方优先级事实。
- `PublicTileView` 不携带他家暗牌或未来牌墙；本人暗牌只进入未见容量扣除，未见可复现的信息越权。当前条件公开计数的两个缺陷说明“只使用公开信息”仍不足以保证物理容量正确。

## 修复复核（2026-09-30，审查后同日）

上述两项是修复前发现，已分别加入回归并修正。跨吃/碰的第五张现在返回 `public=None、unseen=None、evidence=unknown`；混合留河/移河的同码旧弃牌通过每次领取的 `retained_in_river` 身份区分，本次移河不再错误扣重叠。另补反例：声称本次被领牌留在供牌者河中、但该河没有同码牌时，即使别座河有同码也返回未知，不得把别座牌充当物理重叠。修复后公开牌定向测试 67 项通过；与条件响应、规则、模拟和离线驱动等合跑的集成回归见[进度记录](./PROGRESS.md)。这些结果只关闭本报告的已知反例，不把整个 P2 机械门标为通过。
