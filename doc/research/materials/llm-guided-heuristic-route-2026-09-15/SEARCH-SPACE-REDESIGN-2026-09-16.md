### 1.1 动作价值的数学边界

**终局倍率的乘法，与互斥终局结果的期望加法同时成立。** 积分目标的理想动作价值为：

~~~text
Q(a | I) = Σ_o P(o | I, a, 后续各方策略) × 本座位净增积分(o)
~~~

`I` 仅含玩家依法可见信息；`o` 包含自己胡、他家胡和流局等互斥结果。若目标是阶段晋级，把积分替换为 §2 的终端效用。真实概率未知，候选可以构造确定性近似，输出仍称“评分点”。

必须区分：

- 具体成胡终点的番因子及四家支付由唯一规则源计算。
- “自己胡概率 × 自己胡时条件平均得分”是合法期望分解；不能因计番为乘积而禁止。
- `E[log2(fan)]` 与 `E[fan]` 目标不同，前者不得冒充期望积分。
- 各价值族可能描述同一个结果，不能把重叠事件当互斥结果重复累加；也不能因此禁止所有加法。
- 一步有效牌集合是“摸到其中任意一种可推进”的替代集合；不是完成一个目标必须集齐的缺牌多重集。
- 未见张数不是墙内余张真值，进张数×张数×巡数也不是已校准概率。

反例纳入合同测试：A 固定倍率 4，B 以 40% 得倍率 16、60% 得倍率 1；期望倍率 B 更大，期望 log 倍率 A 更大。此例只验证目标差异，不作为杭麻场景。

| 自然桌赛积分 | 可诊断速度、大额结算与支付代价；不能作为进入新阶段评估的“必须显著为正”条件 |
| 赛事覆盖 | 工程闭环先覆盖四人中间阶段；海选全榜、决赛加赛另建目标合同，不凭本结果宣称全赛事提升 |

【官方已确认】指南 v34 的排名键链为 `total_score → place_points → god_count → user_id`；决赛采用纯总分并加赛。依据：[2026-09-15 入库快照](../../doc/references/official-guide-v34-content.txt)第 375—377 行及[赛事流程](../../doc/official-tournament-flow-2026-09-03.md)§5。本版不重新定义官方规则；以上快照不是对未来平台版本的保证。

**同分缺事实不得随意排序，也不得删掉这类根。** 现有阶段合同明确离线 `god_count` 缺失。首版先判断缺失键是否影响前二边界：不影响时 U 确定；影响时保存 `U∈[0,1]`，配对差保存区间 [候选下界−基线上界，候选上界−基线下界]。统计同时给目标上下界，留存保守使用差值下界并保留未分辨标记。确认不能靠任意 user_id 提前打破未知 `god_count`。后续如补模拟侧完整获取账，需与官方口径对拍并升级结果版本。

具体算法：按已知 `(total_score, place_points)` 排序，焦点所在并列块的可能名次为 `[a,b]`，其中 a=严格更高者数+1、b=严格更高者数+同块人数。b≤2 则 U=[1,1]；a>2 则 U=[0,0]；其余为 [0,1]。这是**识别区间**（缺事实造成），另算抽样置信区间，二者不混。双方策略、输入与执行轨迹完全相同且可证明结果相同时，配对差恒为 0，不能用两个独立区间运算把自比较变成 [-1,1]。

**必须新增显式 `group-only` 阶段入口。** 现有 `sitin_stage --participants 4` 按档位进入决赛，不能作为本目标的实现。复用 `plan_group_tables / accumulate_stage / rank_ledger`，但另做上述前二边界计算，不采用旧诊断字典序兜底。

**目标合同身份必须包含**：目标函数源码摘要、赛制、每桌单局数、底分、规则配置、排序与未知处理、对手池、座位方案、阶段信息投影方式。变化即新实验，不能拼旧结果。若用户以后明确要求“前二且正积分”，建立单独 `joint_target_v1`，不得静默更换本版 U。

## 4. 固定骨架与可演化区域

**骨架负责提供充分的合法分支和可靠执行；候选拥有最终动作评分。**

| 永久固定的约束 | 一次实验内冻结、可另版修改的实现 | 首版即可演化 |
| --- | --- | --- |
| 规则语义、玩家信息边界、唯一规则源 | 路线分析上限、顺序与近端范围 | 路线之间的选择、组合和相互作用 |
| 合法动作集合、拒绝过滤、紧急动作保留 | 参考机会/威胁代理及版本 | 使用/忽略参考代理，自行用事实构造机会近似 |
| 返回结构、有限数、稳定排序、确定性 | 场景生成器、评估面板、留存与父代调度 | 速度、期望积分近似、支付风险、排名处境的取舍 |
| 原截止、网络余量、资源限额、失败降级 | 工具目录及候选代码白名单 | 分段、非线性、交互、参数与局面选择逻辑 |
| 候选不能修改评估与标签 | 规则事实结构的版本 | 对全部合法动作进行相对比较 |

**不再设“必须证明权重不能表达才开放聚合”的门槛。** 当前入口从一开始就能产生完整动作评分。原始输入被删掉或外层固定优先级限制表达能力，可用确定性反例证明，不要求先耗费桌赛证明。

### 4.1 新策略运行顺序

1. 应用层沿既有路径先取得合法紧急计划。
2. 唯一规则源生成合法候选及本版有界分析事实，计算时间计入原窗口。
3. 构建只读 `ScoringView`；不包含 WorldState、研究标签、种子、结果、token 或评估分组身份。
4. 调用一个可演化入口 `score_actions`，一次读取同窗全部动作与分支。
5. 验证完整返回，按分数降序、`action_key` 升序稳定排列；沿现有受控接口填入从 1 开始的 `rank`。
6. 应用拒绝过滤、紧急动作保留与提交前规则复核；记录器经既有端口落审计。

**新入口明确允许比较合法 Hu 与其他合法动作。** 这是显式的新排序合同 `hu_mode=compare_legal`，不是放大旧 delta 绕过 V2 的优先层；“立即胡永远支配继续”不是规则定理。首批种子应包含“立即胡优先”的对照实现，但骨架不强制它。开工准入必须同时覆盖“应及时胡”与“可研究等胡”的正反例；胡牌是否更优由真实结果检验，规则只证明是否合法。紧急动作保持现有 `HangmaRules.emergency_action` 的 Pass/Discard 路径，不能误称已有胡牌保底；旧策略优先级不修改。

### 4.2 事实与参考工具目录

**确定事实归 hangma；策略参考代理归 policy；完整世界与续打归 simulation/offline。** 候选只读不可变投影，不允许任意 import 规则私有函数。

| 输入组 | 必须保留 | 未知/范围 |
| --- | --- | --- |
| 玩家观察 | 自己牌、公开副露与牌河、当前窗口、庄闲、公开规则状态、墙余量 | 使用 `PlayerObservation` 白名单投影，保留已知性；不猜他家暗牌 |
| 桌赛/阶段 | 座位 0—3 积分、单局序号、有效阶段类型、可见排名/剩余机会及新鲜度 | 无权获知或陈旧则为空；模拟器不得投影其他进行中桌赛的未来结果 |
| 动作 | 稳定 `action_key`、规则动作类型、合法身份、立即结算 | 集合只来自 `RuleAnalysis` |
| 后续分支 | `(action_key, followup_key)`、机械转移后的可见手牌、普通/七对进展、关键规则状态 | 吃碰后不同弃牌不得预合并成一个牌效最佳分支 |
| 路线 | 分支、链、四白、爆头与合法组合的标签、条件见证/距离、资源竞争、关闭依据 | 已证关闭、未分析、可达但兑现未知分开 |

| 参考代理 | 有版本的机会/他家先胡/支付强度参考值，附假设、单位、可用性 | 可不用；没有校准证据时不标“真实概率”或“严格下界” |

昂贵分析优先在规则侧按固定上限算一次。首版候选工具仅提供对白名单事实的纯计算与查表；不提供在线完整续打、不提供无界重新枚举向听。需要新增推导工具时进入工具目录版本和耗时门禁，不能临时绕过接缝。

## 5. 输入、输出与失败合同

**接口名称是拟实施合同，现源码尚无这些新类型。公共类型改动需同一提交更新文档、编解码、调用方和契约测试。**

~~~python
def score_actions(view: ScoringView) -> ScoreBatch:
    """根据同一动作窗口的只读可见事实，返回所有合法动作的完整评分。

    view：不含隐藏世界、实验种子或赛后结果；包含同窗候选及后续分支。
    返回：SCORED 加完整动作评分，或 ABSTAIN 加明确原因；评分点越大越优先。
    错误：抛错、非有限数、遗漏/重复/越界动作、超工作量均使本窗口整批失效。
    副作用：无；不读时间、随机源、网络、文件，不修改输入。
    """
~~~

| 类型/字段 | 精确含义 |
| --- | --- |
| `ScoringView.schema_version` | 固定 `sitin-scoring-view/1`；不兼容变更升主版本 |
| `visible_state` | §4.2 的白名单只读观察；不直接给完整 DecisionRequest，去掉运行关联键与研究元数据 |
| `competition` | 可见赛事上下文与可用/陈旧掩码；积分基准为本阶段/本桌分别命名 |
| `actions` | 按 action_key 升序的不可变动作表；附不可变后续分支和路线 |
| `analysis_profile` | 语义版本、固定工作量上限、截断范围；不含计时器或可变缓存句柄 |
| `reference_features` | 代理值、版本、单位、缺失原因；与规则事实分开存储 |
| `ScoreBatch.status` | 仅 `SCORED` 或 `ABSTAIN`；不能部分成功后用 0 补齐 |
| `ScoreBatch.entries` | SCORED 时对输入全部动作恰好一项；ABSTAIN 时为空 |
| `ActionScore.action_key / score` | 动作键与有限浮点评分点；不跨候选比较其绝对量级，不当实际积分 |
| `ActionScore.trace` | 有界结构化解释：分支选择、所用事实键、代理/分项、组合方式；非线性项不强求相加等于总分 |
| `ScoreBatch.reason` | ABSTAIN/降级原因；不是用某个特殊数值表示未知 |

适配现有 `RankedCandidate` 时，将新总分放入单个 `ScorePart`，保持既有 `total_score == sum(score_parts)` 不变量；非线性机制明细另放有版本的 trace，不拆成虚假的可加贡献。

### 5.1 分支与未知的具体处理

- 路线状态为 `WITNESSED / OPEN_UNCERTAIN / CLOSED_PROVEN / UNANALYZED`；进展为 `ADVANCE / SAME / RETREAT / CLOSE / UNKNOWN`。前者回答证据状态，后者回答动作相对变化，不混成三态。
- 没有更远路线见证时，仍可用分牌型距离、有效牌及保留结构评分；不得因未枚举而把其真实机会设为 0。
- 候选清单声明必需字段；窗口缺必需字段则 ABSTAIN。可选字段缺失由候选显式处理；不能把未知的 0 分排在已知负分之前。
- `SCORED` 返回不全、NaN/Inf、布尔冒充数、动作键非法等，整批失败。降级到已备好的合法紧急计划，不悄悄拼 V2 分数。
- 同一候选的吃碰估值与随后弃牌决策必须使用相同评分准则。可以为比较构造规则提供的后继视图，但不能在评分前固定选牌效最优弃牌。
- 未来自摸/杠补及他家行动不是确定后继；按条件见证或未知分支表达，禁止补出未来牌值。

### 5.2 分析完整性和数值

工作量上限来自版本化 `AnalysisProfile`，首版复用 `ValueAnalysisLimits` 的机制。各动作先取得最低进展事实，再以确定顺序追加路线；不得把预算全花在 action_key 靠前的动作，导致后面的合法动作丢失。达到上限输出 PARTIAL 与截断原因，原合法集完整保留。

分数不做逐动作钳制，不沿用 delta 的 `bound` 意义。候选声明有限数值范围用于异常检查；越界整批失败并审计。单调缩放不应改变排序；若采用归一化，必须是候选明确实现、测试过的共同变换，不在外层偷偷调整。

## 6. 候选代码、运行安全与完整身份

**安全、覆盖和强度是三种不同检查。新入口使用新 schema，不重解释旧 admitted。**

### 6.1 受限代码与截止时间

**2026-09-20 用户裁定补充：** 当前计数额度不再作为否定机制研究价值的单一依据。默认额度失败的候选，可以在另行冻结的有界离线配置中接受安全检查与效果研究；成绩有价值时再做等价提速、编译可行性或机制简化。研究通过不等于发布通过，具体实施顺序、身份和历史结果边界见[性能研究与发布裁定](R10-PERFORMANCE-RESEARCH-AND-RELEASE-2026-09-20.md)。默认执行额度仍为100,000；显式研究配置200,000现已接入受监督的准入、计时、真实输入回放、条件/自然评价、反馈和只读核验。依赖变化使新运行身份更新，历史结果不补签。自动档案状态机尚未贯通研究配置，显式拒绝研究额度开迭代；研究机制单独留存，不能自动成为部署冠军。

首版生成 Python 的受限子集：一个导出函数，可有无递归的局部纯辅助函数；仅允许对有长度上限的输入/局部集合迭代。禁止 while、递归、动态执行/导入、反射、文件/网络/进程、全局可变状态和读取时钟/随机数；调用对象只来自冻结白名单。集合大小、循环工作量、幂/整数膨胀及输出 trace 大小均须限制，不能仅做关键词扫描。

第一版初始限额为工程配置：规则分析最多 2,048 次扩展、每动作最多 128 条条件路线；候选最多 100,000 个计数操作、局部单集合最多 4,096 项、源码最多 64 KiB、结构化 trace 最多 32 KiB。每循环迭代和允许调用计费，内置 sum/sort 等按输入长度保守计费，禁止不计费的批量计算。算术使用有界整数/有限浮点，拒绝大整数膨胀和不受限幂。数值范围、总分支/总路线内存上限及具体白名单在 A 包的机器合同冻结；默认不开任意 math/第三方库。限额不是毫秒保证，B 的基准不通过就缩小有版本的分析配置并重评；不得删除合法候选来凑限额。

实施者须提供「静态子集检查＋循环/运算计数限额＋实际整链计时」三个层次。插桩由固定执行器进行，候选不能捕获工作量耗尽异常继续执行；源码、插桩版本和执行依赖都进入身份。规则分析自身另有工作量上限。首版不以通用插件/任意 Python 沙箱替代这一小接缝。

离线所有装载、模块初始化、构造和执行复用 `sitin_process.run_supervised`，到期终止整个进程组；静态检查通过不免除隔离。真实运行只装载冻结且审核过的候选，不在生产目录动态扫描生成文件。

受监管子进程是故障隔离，不是操作系统安全沙箱。父进程只解析与验证源码，禁止候选模块顶层执行代码，先编译为上述受限产物才在工作进程装载；工作进程不注入凭据。若未来允许任意 Python，则须另建文件/网络/内存等操作系统限制，不能复用本安全声明。

**异步 timeout 无法打断堵塞事件循环的同步代码。** 不得仅引用 `_guarded_choose` 就声称新评分器按时返回。新评分器与规则分析在固定工作量下完成，所有允许计算路径需通过最大输入/故障/满载门禁；预算不足在进入增强前就用保底。若受限执行器仍不能提供有界工作量证据，该候选不可发布，不能延长 1 秒/3 秒原窗口。

### 6.2 新门禁记录 `sitin-action-value-admission/1`

下表“执行安全通过”须绑定所声明的执行配置。默认配置计数超额仍为该配置 FAIL；不能改写旧结果，但不排除按上述2026-09-20裁定取得另一有界研究配置的资格。权限、规则、数值、结构和隔离约束失败仍须先修复，不得仅提高操作额度放行。

| 层 | PASS 条件 | 不足/失败怎样处理 |
| --- | --- | --- |
| 执行安全 | 输入权限、代码子集、全链限额、输出合同、隔离故障、保底和审计测试通过 | FAIL 禁止效果执行；未知关键安全性质不放行 |
| 覆盖 | 胡/过/吃/碰/杠/弃牌、路线组合、未知与缺史都有逐类结果 | 某机会样本不足标 INSUFFICIENT；不能汇总抹平 |
| 受控研究资格 | 执行安全通过，场景生成器合法、数据和候选身份绑定、资源有余量 | 可在声明条件/自然面板取证；不等于发布准入 |
| 效果 | §8—9 实际续打及统计结果 | 不显著可进有限探索档案；运行失败不补零 |
| 发布资格 | 独立确认、规则一致性、实际阶段范围与时限/恢复全部通过，再由人审核 | 本文不触发发布，也不降低旧默认策略门槛 |

旧 G-1 只计 `choose` 或使用宽于实际 1 秒窗口的预算，不足以验收本版。新计时覆盖紧急路径、规则分析、事实构建、评分、计划输出；同时记录各段和全链 p50/p95/p99/最大值，按实际 DecisionBudget 中的剩余额度检查，保留固定网络余量。全机并发按 §11 测，不能把候选函数几毫秒当整窗口耗时。

### 6.3 身份与恢复

`candidate_id` 由以下规范化内容取哈希：候选种类 `action_value_v1`、原始/执行源码、有效参数、输入输出合同、骨架、规则/特征/代理版本、分析上限、执行器版本、第一方传递依赖摘要。生成模型、提示词、算子、父代、调用账单作为出处另存。

`evaluation_id` 另绑定目标合同、候选/基线、对手、面板/来源根、随机映射、换座、续打终点和统计版本；语料不塞进 candidate_id。恢复必须逐项匹配，依赖变化即拒绝续写旧结果。缓存仅在完整 evaluation_id 相同时命中；不能只按手牌或 seed 命中。

## 7. 条件机会与正常开局面板的构造

**首版不依赖尚未合入的隐藏世界采样器。优先从完整合法模拟轨迹截取机会，保留原世界和阶段快照。**

### 7.1 冻结面板与划分

先生成不可变根清单，再评候选。以 `source_root_id` 划分开发、刷新开发和独立确认，来源相同的前缀、窗口、续打随机数及换座不可跨集合。搜索进程不能读取确认种子、逐例结果或汇总反馈。

首版对手有两个独立情景：H 为三家冻结 V2；M 为固定 V2、V2_white_guard、V1 各一家。名字只是现有对照身份，强弱未知。H/M 分开报告，不猜官方对手比例；开发默认按两情景等权形成**声明的工程混合目标**，每个小批均衡配额。发布结论限定该混合与各分层结果。

正常面板从阶段零分、合法自然发牌开始，持续完整 2 桌开发阶段；桌赛内部按运行时 Rounds 完整执行。根内 4 个座位轮换、双臂使用同一对手与随机映射，轮换结果先在根内平均。其他参赛者身份随合同固定，候选只替换本座位策略。

### 7.2 机会生成算法 `legal-prefix-v1`

1. 使用固定行为策略 V2、冻结 H/M 对手和自然洗牌根，模拟完整合法前缀；行为策略不随正在评估的候选改变。
2. 每个生成尝试预先分配一个子场景，使用独立根；在候选行动之前，仅用玩家可见事实判断场景谓词，首次命中时截取。首版同一来源根只贡献一个样本和一个主子场景，其他家族仅作标签；不把同轨迹复制到不同子场景增加样本数。
3. 保存阶段累计账、MatchSpec、未完成赛程和各座位合法动作前缀、截取窗口与观察摘要；通过模拟器公开 start/frame/advance 重建并核对摘要。同进程可复用不透明不可变 WorldState 分叉，持久化恢复用合法前缀，不直接写私有字段或要求先实现通用 WorldState 序列化。
4. 相同场景候选/基线从完全相同快照出发，各自持续决策到声明阶段终点；世界只留在模拟器，策略接收各自 PlayerObservation。
   若仅为研究同一单局内的合法动作差，可从同一不透明世界及公开状态一致的隐藏重采样样本双分支续打，并通过 `SimulationEngine.export_hand_settlement` 读取已完成单局的最小结算。此出口不生成可重放的 `full_world` 牌谱；抽样分支只能做行为/机制诊断，不能替代完整桌赛与独立确认。
5. 随机过程按固定阶段/桌赛/牌墙身份派生，不能按“调用随机数第几次”在分叉后错误对齐；策略差异导致结果分叉是实验的一部分。
6. 每子场景首版最多 256 个前缀尝试，另受实际桌赛预算约束，任一上限先到即停。未找到足够样本标 INSUFFICIENT，保留尝试/未命中/未知计数；不得改状态字段冒充合法世界。可增加带合法动作见证的脚本前缀，但必须独立生成器版本和分层报告。

> **指定根路径的尝试语义（2026-09-18，P9 FAMCOST 补齐契约缺口）**
>
> 第 1–6 条声明的是**生成**语义（按子场景搜索独立根、命中即截取）；**指定根**路径
> （家族声明/补根点名 rootNNN）此前只写进实现：单根面板只跑被冻结的那一座牌山、
> **一次尝试**，读数里 `cap` 借用调用方的 `attempts_cap`（8）而 `total=1`，
> 两者自相矛盾。现明文约定：
>
> - **指定根 = 单根单次**：家族声明/补根点名根的身份（生成器 × 子场景 × 情景 ×
>   面板种子 × 根序号）决定同一座牌山，重复跑同一根只会得到同一前缀同一判定
>   ——因此不重试同一根换取"运气"，也不换根顶替；
> - 面板读数必须自洽：`prefix_attempts.cap = 1`（真实上界）、调用方的预留额另存
>   `requested_cap`，放弃时给具名原因（`attempts_exhausted_reason`）；
> - **换牌山走声明层**：某格需要 2 根而请求根不见证谓词时，在**预算门**下做
>   **有界独立根搜索**（逐格上限 12 个候选、全局上限 24 次探针），只把见证到谓词的根
>   写进该格的**有效声明**；请求逐字保留、逐候选根留痕；凑不齐即具名停因
>   （`family_refresh_declaration_unfillable_old_seats_kept`）并保原席原 epoch。
>   逐格配额与预算都不得放宽（详见 §7.3 的同日修正）。

现有 `drive_match` 无条件从 engine.start 开始；C1 必须提取共享驱动循环，新增受控中途续打入口，不能复制另一套推进逻辑。阶段快照必须保留已完成桌赛积分与当前桌已发生积分；重建到某帧时尚未推进的所有响应者重新按该帧观察决策，不能沿用基线预先选好的他家响应。首版候选无跨决策可变记忆，不需要从基线前缀恢复候选私有记忆。

该方法估计的是固定行为分布到达条件 C 后的效果，不是候选自身到达 C 的频率。正常开局面板负责检验候选是否提前创造/破坏机会。首版不从历史窗口自动恢复未知完整世界；旧窗口语料只用作行为和字段验证。

### 7.3 首版场景矩阵

四个专长家族对应规则价值来源，组合场景可以有多个标签；每族至少有以下两种子场景，规则事实与策略假设分开记录。

| 家族 | 机会子场景 | 反例/代价子场景 |
| --- | --- | --- |
| 分支 | 普通型与七对/豪华结构存在可见取舍，包含吃碰后不同弃牌 | 关键进张耗尽、开门代价或距离明显增大 |
| 动作链 | 合法财飘/杠及续链入口，包含已有倍率上的升级 | 墙短、补牌结果未知、追链减少普通成胡机会 |
| 四白 | 手留白与链内飘白共同形成的保留/推进机会 | 不满足等值条件、归因缺失、为凑四白付出代价 |
| 爆头 | 保持/形成/升级条件与其他路线组合 | 合法性门控不满足、继续等待可能丢掉已可兑现结算 |

每族再加阶段处境标签（领先/追分/接近边界）、窗口动作族、近端/早期保留、合法组合与未知；标签不强求笛卡尔积全穷举。场景谓词只说明“这里存在待比较取舍”，不得把“最终胡出大牌”或“人认为应保留”作为入选条件。

#### 八个机器谓词的冻结合同

**A 包先交谓词 JSON 与纯函数，C1 只执行，不能自行解释“机会好坏”。** 主 ID 固定为 `branch_open/branch_cost/chain_open/chain_cost/four_white_open/four_white_cost/baotou_open/baotou_cost`。初版使用下述共同算法；经验阈值只定义采样条件，不传入策略作为强制偏好，也不伪称概率。

谓词读取同一根规则事实中的 `wall_left`、各行动分支的 `combined_shanten`、`family_progress`、`route_status`、`support_remaining`。**`wall_left` 的定义是「可摸牌墙余量」**（见本节末的 2026-09-18 修正）。`combined_shanten` 是该分支等待态已知分牌型向听的最小值；`support_remaining` 是该路线一步推进有效牌的未见枚数总和，牌码去重，不是目标缺牌集大小或墙内真值。没有同一分析范围的比较值则 UNKNOWN。

| 家族 | `family_progress` 的确定性来源；不允许调用被测评分器 |
| --- | --- |
| branch | 同一普通/七对路线在动作前后等待态的向听距离，减少为 ADVANCE、增加为 RETREAT、不变为 SAME；开门使七对关闭为 CLOSE；豪华细分未分析时 UNKNOWN |
| chain | 已知规则转移后的链次数相对动作前：增加/相同/减少分别 ADVANCE/SAME/RETREAT；不预测未来必有杠或飘 |
| four_white | 已知合法状态中距“四白等值条件”的距离 `4−(手留白+链内飘白)`，减少/不变/增加分别 ADVANCE/SAME/RETREAT；缺归因 UNKNOWN，不因单纯弃白就写 CLOSE |
| baotou | 当前与动作后权威/同源推导爆头状态：False→True 为 ADVANCE，True→False 为 RETREAT，相同为 SAME；未知转移为 UNKNOWN |

对家族 f，枚举来自**不同当前合法 action_key** 的分支对 (b,c)，按键稳定排序；寻找至少一对满足：

1. b 对 f 为 ADVANCE 且 c 为 SAME/RETREAT/CLOSE；或者 b 为 SAME 且 c 为 RETREAT/CLOSE。b 的路线状态必须为 WITNESSED 或 OPEN_UNCERTAIN，且自身不被证明关闭。
2. b/c 都有可比较的 combined_shanten；记 `gap = shanten(b)−shanten(c)`。支持计数与墙余量必须已知。
3. `f_open`：`wall_left≥16 AND support_remaining(b,f)>0 AND gap≤1`。
4. `f_cost`：`wall_left≤8 OR support_remaining(b,f)=0 OR gap≥2`。

每谓词返回 TRUE/FALSE/UNKNOWN 与事实见证键。已知有满足分支对则 TRUE；所有必要比较已知但均不满足则 FALSE；没有确定见证且可能改变判定的值缺失则 UNKNOWN。UNKNOWN 不作为接受样本，单列原因。

> **2026-09-18 修正（P9 FAMCOST，Lead 裁定：判据不动、单位与判别字段修正）**

> 1. **`wall_left` 的单位 = 可摸牌墙余量**（`max(0, 官方公开余量 − 保留区 20)`）。

>    测试房 30,096 条快照逐窗对拍确认开局恒为 83 = 136 − 53、且等于

## 8. 配对统计、反馈与独立确认

**主评估使用原始终端 U；不裁剪合法大额结算，不按被测评分器的分数评价被测评分器。**

### 8.1 统计量

对相同来源根 r，先按预定座位/续打重复数平均各臂 U，再取差 `d_r`。同一个来源根跨多个窗口或标签时仍是一个聚类单位；不能按决策/单局/换座/隐藏样本数量扩大 n。

每个面板/子场景至少记录 `n_roots、mean_delta、standard_error、interval、status`。无根/运行故障/目标不可计算分别标注，禁止补零。原始记录仍保留，即使候选退出。

开发展示复用根级配对区间；它只表达本次抽样不确定性，不作为反复看数后“已证明提升”的证据。同分缺键的 U 区间分别统计上下界。机会家族开发值为机会/代价两个子场景均值各占 1/2；这是冻结的条件混合，不还原自然分布。每个家族同时展示两子场景原值，不能只报有利部分。

### 8.2 反馈严格分三段

1. **事实**：同一可见观察下双方分别选什么；触发了哪些事实/未知掩码；运行成本和异常。
2. **关联结果**：在冻结面板/来源根上的终端差、区间、覆盖与反例表现。
3. **机制假设**：可能是哪种取舍造成差异、下一版准备怎样改变、预计在哪类反例失效。

未做单动作反事实实验，不写“这个动作造成了全部分差”。轨迹分叉后不按动作序号强行对应。给 LLM 的是开发结果与失败原因；不含确认集、未来牌墙真值或要求线上识别实验编号的提示。

### 8.3 独立确认合同

首版只确认 **1 个冻结完整候选**，与固定 V2 基线比较；确认预算预留，不被搜索借用。选择依据来自开发档案，不要求自然桌赛均分先显著为正。

**提名算法**：停止生成后，候选池为当前档案全部安全有效身份；使用同一正常通道 `panel_epoch`，将池中每个候选缺失的开发根补齐，再按 §9.2 整体席排序键取第一名。V2 的虚拟配对值为 0；最高候选值≤0 时不提名，保留档案并报告本次开发未选出整体优胜。补齐成本必须预留在开发账，不能动确认账；补不起则输出 `nomination_pending_budget`，不偷偷排除昂贵候选或拿不同根集排序。提名池、面板、排序结果及候选源码一并冻结，之后才允许打开确认数据。

确认使用从未进入生成/调度的自然阶段根，固定样本数与目标后一次性分析，不反复“再加几根直到显著”。按根级配对均值报告 95% 区间；二值/区间 U 同时提供基于有界差 `[-1,1]` 的保守界，作为发布判断下限，避免少量全零样本给出虚假零误差。若区间不能排除无提升，保留稳定版本；预算不足则只交付开发结论。置信方法、抽样配额与对手混合在运行前进入合同。

首版机器通过式固定为一侧 5% Hoeffding 下界：`LCB = mean(L_r) − sqrt(2 × ln(20) / N)`，其中 L_r 为每个独立自然根的保守配对差下端，N 为根数；仅 LCB>0 支持目标改善。等权 H/M 分层须均衡，使样本平均的目标与声明混合一致；不能按完成快慢混入不同权重。这个界适用于有界独立根但较保守，N=100 时扣减约 0.245；有限预算可能不足以确认小效应。开发仍可继续保留专长；以后采用更高效确认方法需先冻结适用条件并另版验证，不在看到结果后换检验。[Hoeffding 1963 原始出处](https://doi.org/10.1080/01621459.1963.10500830)；此处系对取值宽度为 2 的独立根均值应用有界尾界。

若查看确认后再修改候选，原确认集转为已消费开发数据，新候选需要新留出与相应预算；不准反复重用同一确认集发布。完整赛事覆盖、实际参数和真实时限验证仍是最终发布条件，本版工程开发面板本身不代替它们。

### 9.1 容量与资格

- 档案最多 8 个不同 candidate_id：整体 2 席、四个家族专长各 1 席、探索 2 席。
- 同一候选可有多个席位标签，只存一份；不因去重而临时增加同类容量。**该句是记账/容量
  条款，不是兼任授权**：一个候选不得同时持有整体席或家族席与探索席——探索席的排除集
  = 在案 overall 与四家族席持有者（§9.2 规则 3），"同一候选多标签"只描述同一份候选在
  多个**已入席**通道里被引用时只存一份条目，不描述探索席可以重复容纳在案席者。

  而是以本次事务**提交后的**在案席位为排除集与同行为去重参考，再与该次席位变更
  **一次原子提交**（同一份档案写，不另开旁路）。
- 安全 FAIL、效果执行故障且未修复的候选不能当父代；安全通过但效果未分辨者可进入有限探索席。
- 旧候选可作为对照与生成材料；只有新接口身份才能占新档案并被调度为新父代。V2 是固定比较基线，不占 8 席。
- 整体/专长席至少需要相应规定面板完成；缺某一子场景时不把它填零争专长席，可保留探索身份。

### 9.2 选择规则（开发启发式，不称统计证明）

在相同版本的公共开发核心根上比较：

1. **整体席**：按正常阶段目标差均值排序取前 2；同分依次按未知目标比例较低、**整链成本较低**、candidate_id 字典序。目标有区间时用差值下界均值，并标未分辨。
   - **整链成本 = 确定性预算单元**（口径 v2）：样本以其**冻结期望清单**声明的完整桌实例数为单位（臂数 × 每臂每阶段桌数，§11 的预算单位），逐根求和得条目的 `total_cost`。它必须是**冻结输入的纯函数**：同输入 → 同排序 → 同席位。`elapsed_ms`/`wall_sec`/`cpu_sec` 等墙钟实测值**不参与排序**，只写进 `recorded_cost`/`recorded_total_cost` 供审计。
   - 夹具/旧档案若直接以数值声明样本费用，该数值即视为确定性输入原样使用；同一矩阵下预算单元会退化为常量，tiebreak 自然落到 candidate_id（这正是"同输入同结论"的要求）。覆盖不同（根数/桌数不同）的候选仍按预算单位区分贵贱。
2. **家族席**：该族机会/代价两子场景等权均值最大者入席；并列同上（同样按确定性整链成本）。无需整体值显著为正；大牌次数不用于排序。
3. **探索席**：从**剩余安全候选**选行为签名最不同者。签名使用固定可见窗口上实际 action_key 与缺失掩码，距离为窗口动作不一致比例；采用到已入档候选的最小距离最大化，迭代选 2 个；同分优先证据较少者，再按 candidate_id。
   - **"剩余"相对提交后的在案席位**（口径 v2）：剩余集 = 未持有在案 overall/家族席、且行为签名与**在案席持有者**不同的安全候选；同行为去重参考就是在案席持有者的签名摘要（规则 4）。选择实现唯一来源 `sitin_archive.select_exploration_seat`；`update_archive` 与档案事务的提交点都调用它（前者以本次重排出的席位为在案席位，后者以**提交后的**席位为准）。
4. 行为与源码去重分别记录。源码不同但同签名可保留结果缓存/血缘，不凭代码排版增加探索名额。
5. 没有数据时不得以候选自报价值填档；先用种子和 I1 获得真实结果。

**通道面板版本与替换复核**：正常通道和四个家族通道各持有 `panel_epoch`，其根集是该通道核心根＋历次已提交刷新根。挑战者先补齐该通道当前全部根；均值有望入席时，预留新刷新批，并给**本次参加通道重排的所有身份**补齐（整体通道含两个原席、挑战者及其他同时参与排序者；家族通道同理）。全部完成后原子提交新 epoch，统一用新根集重排。只完成部分身份时保持原 epoch/原席，结果暂存 pending，不混合新旧均值。每受影响子场景刷新 4 根，整体刷新 4 根，H/M 配额均衡；不足预算则保持原席，挑战者留在探索候选队列。替换是开发选择，不冒称显著击败；刷新记录以后不能流入确认集。

### 9.3 父代与算子调度

首版生成序列固定，调度随机源与麻将世界随机源分开记录：

- 初始化：两个人工种子 `efficiency_seed` 与 `route_value_seed`，均为完整评分函数；另进行一次 I1。种子只是工程对照，不预定“正确答案”。
- 此后每 4 次提案：3 次 M1、1 次 I1；失败/重复也消耗本次调用额度，不免费无限重试。
- M1 父代通道按“整体→专长→整体→专长→探索”循环；专长家族轮转，通道内部按最少被使用次数、candidate_id 排序选择。
- 空通道跳到下一非空通道；档案为空时用 I1，不把无评价失败候选伪装成冠军。
- 每次只生成一个候选代码产物；解析修复最多 1 次且单独计调用/token。
- 至少取得一条真实“条件结果→反馈→M1→同合同重评”后，才算最小进化闭环完成；后代未提高也可以完成工具验收。

E1（多父代产生不同思路）、E2（提炼共性后产生新思路）、M2（保留思想的参数修改）、M3（分析并删减冗余组件）作为后续算子扩展；定义与 EoH 对齐后单独测试和记账，不作为首版依赖。专长组合后得到的是新完整候选，不能未经重评直接在线拼装多个冠军。

### 9.4 一次迭代的固定顺序

~~~text
读取剩余预算并预留本次最大费用
→ 选算子/父代，生成代码与四字段说明
→ 固定执行器隔离装载，安全与接口检查
→ 公共行为面板：覆盖、签名、去重
→ 条件机会面板＋正常阶段面板（允许分批，但都计真实执行）
→ 来源根配对统计，生成三段反馈
→ 按通道挑战与刷新复核更新档案
→ 原子保存候选、结果、档案、调用与执行账
→ 未到预算/停止条件则继续
~~~

不因正常面板未显著提高就跳过已声明的机会面板。对全无行为差异者可暂停扩样，但记录“本面板等行为”，不能宣称全域等价。

## 10. R-E 提示词合同与 R-F 的启用条件

**提示词由机器合同渲染，不能与装载器各自维护两套允许范围。** `TaskContract` 必须含：

- 本批目标、工程面板边界、终端 U 与当前可见赛事信息。
- score_actions 完整签名、字段含义/单位/可空、工具目录、数值与工作量限制。
- 候选负责完整动作取舍；不修改规则、接口、评估器或运行配置。
- 源码模板和结构化四字段：触发条件、改变的动作/分支、预期方向、反例。
- M1 附父代原始源码与完整身份、三段开发反馈；I1 不附伪造实验成绩。
- 所有研究数值标明单位、根数、终点和不确定性；不要求模型自报“预计提分 N”。

现有“只设计评分调整机制”“不决定取舍”要改为“负责候选内部动作取舍，不自行判定实验优胜或发布”。可用工具的使用方式由候选决定；安全与合法性约束不由候选决定。

**R-E 可以一直使用。** 仅在有效候选重复、提案覆盖不足且已排除输入/评估瓶颈时，考虑 R-F 的版本序列提案对照。对照需匹配模型、生成 token、评估预算、初始候选与反馈，并做独立搜索重复；解析通过率不能代表更容易发现强策略。当前不为 R-F 建并行框架，不预建岛屿服务。

## 11. 预算、并发和恢复

**预算以最新已有用户授权及唯一台账为准，不把方案数字当新增授权。** 旧 v3 写条件 ≤600 桌、自然 ≤1,400 桌、token ≤0.8M；[交接记录](./HANDOVER-MACHINE-SWITCH.md)却记旧搜索 384/384 已用尽、确认上限 0。两者不能自动拼成新余额。执行前核对授权出处与实际 ledger，已用/预留/余额分开；若有更新授权直接继承，不重复询问。没有可核对余额时只做代码、合同与夹具验证。

确认额度单列、默认继承原值 0，不从开发额度擅自划拨。现 `SearchLedger.reserve` 对 confirm 硬禁，未来只有既有/新增授权明确覆盖独立确认时才以新版账本与入口解除；不能只把配置数值改正数。条件额度同时覆盖合法前缀生成、重建、部分桌赛续打和后续完整桌赛；原始“桌”限额保守按每个被启动的桌赛实例扣 1，并另外记录执行单局数与 CPU/墙钟秒。旧稿 S1—S3 零桌声明撤销，任何实际续打从第一笔记账。

双臂最大成本先按无缓存估算：

~~~text
正常阶段成本 = 独立根数 × 4 换座 × 2 臂 × 每阶段桌赛数
条件阶段成本 = Σ场景根(2 臂 × 该根剩余桌赛实例数) + 前缀生成成本
总消耗 = 种子 + 生成候选 + 刷新复核 + 重试 + 确认
~~~

自然首批每候选 4 根、H/M 各 2，后续按 4 根增量；这只是闭环样本，不能证明小效应。若按 2 桌开发阶段，首批双臂四换座为 64 桌/候选。机会配额成本依据实际剩余赛程报价；不得预先承诺 600/1400 桌能确认多少候选。

- 提案前原子预留生成＋最低评价成本，超预算不开新提案；每个失败/重试都记实际费用。
- 确认预算不借给搜索，AIVAT/R-F 增强不得默默挤占它。
- 全机工作进程上限起始为 12；没有实现全局受监管调度则串行，不为每候选各开 12 个。
- 墙钟、CPU 秒、单局数、部分/完整桌赛、来源根、LLM 输入/输出 token 分列。token 口径与已有台账一致，不能只计成功调用。
- 恢复先核对完整身份、在途任务与费用；不能把缺 done 文件视为未执行。进程终止与失联费用按已有保守预留规则处理。
- 停止原因至少区分：预算耗尽、输入缺口、安全失败、长期等行为、已完成预定批次、人工停止。停止不等于有效性被证伪。

## 12. AIVAT 和重要性采样：独立增强，不阻塞主线

**AIVAT 首版默认关闭。若做旁路实验，不进入 LLM 反馈、档案排序或发布结论。** 只使用同一终端效用 U，不先校正积分再阈值化成前二概率。

验收顺序：

1. 冻结所用机会节点、已知策略、价值函数及信息分区；严格核对概率，不能把未校准 opp_win_share 当作已知策略概率。
2. 推导每项校正的期望为零，在可穷举小过程上验证精确期望、确定性动作和信息分区；样本均值接近不是无偏证明。
3. 价值函数如果用数据调过，拟合/选择与测量按来源根分开；首版允许手工冻结启发式，不引入训练模型。
4. 在独立保留根、多个不同策略对上测量**配对差**方差及每根总成本，包含替代状态求值。计算：
   `R = Var(Δraw)×cost_raw / [Var(Δadjusted)×cost_adjusted]`。
5. 报告 R 的不确定性、目标估计差和区间表现；只有合法校正且净效率可靠优于 1 才另版考虑启用。两臂相同校正会相消，单臂降方差不足。
6. 无收益则停用；框架、条件留存和 R-E 继续运行。

重要性采样后置。需明确目标 p、实际抽样 q、完整支持范围和可计算 p/q；条件中途状态没有自动提供自然到达概率。首版条件与自然结果分开即可。自归一化或截断权重不能统一标成严格无偏。[Owen 重要性采样章节](https://artowen.su.domains/mc/Ch-var-is.pdf)。
