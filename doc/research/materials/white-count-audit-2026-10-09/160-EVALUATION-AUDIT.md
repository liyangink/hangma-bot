# 固定160单局的候选评估与研发优先级审计

**结论：用“10桌×16单局”的完整阶段开发参数并评判候选合理且可实施。** 最新五项目标覆盖无白／单白牌效、速度、形状与防守，两类手牌的庄上防守和抢庄按综合积分检验，并保留多白大牌能力。评估扩展为中等工作量；准确估计他家听牌及连庄后续价值更难，首轮不以此为前置。

**本次落地复核补充：** 现有基础可复用，但首版需独立薄装配，不能仅放宽旧R8参数校验。正式P0与RF1研发父版分开，完整画像不是首候选前置；数值声明须有限先导后真实交付。快速净分／晋级增益目前未知。[详细执行规格](./SINGLEWHITE-160-WORKPLAN.md)、[复核记录](./cross-review-2/REPORT.md)

## 1. 赛制前提与统计单位

**`M=10 / Rounds=16`作为用户2026-10-09补充的比赛事实采用，未另行联网核实。** 已冻结的10月8日测试赛确实是10桌、160单局；当前RF1压力房也采用该配置，但压力测试不是策略强度比较。数据诊断仍来自10月4—8日P0/S03冻结资料，不评价新RF1实际强度。[测试赛配置](./test-oct8.md)、[当前RF1入口和验收范围](../vip-route-2026-09-30/evidence/t227-rf1-default-and-live-1/README.md)

固定160的是**每次评估场景的长度**，并非总样本只允许160个单局。应在多个独立赛事阶段（`Stage`，一次独立计分的海选或组内阶段）种子上，基线与候选使用同一组10桌牌山和对手，再换座。一个阶段内的160个单局及同牌山换座结果相关，不能当作160个、640个独立重复。已有配对统计以场景种子为重采样单位；阶段比较也明确以阶段随机种子为独立单位，可沿用。[配对统计实现](../../src/hangma_bot/offline/evaluation_statistics.py:245)、[阶段比较实现](../llm-guided-heuristic-route-2026-09-15/tools/sitin_stage.py:3327)

第一小批可以筛机制和检查失败，不足以确认细小提升或真实晋级概率。后续依据阶段净分差的离散度、预先声明的最小有用提升和置信区间决定样本量；不得反复看到正分就停，也不得按最高分阶段挑样本。听牌指标和定向来源用于诊断，最终增益仍须由新种子的完整160单局阶段承担。

## 2. 同样160单局，目标仍须分阶段

**海选是全场直接晋级排名，16强和8强是四人组内前二；不能统一用“160单局胡得最多”代替。** 现有术语和阶段工具已区分全场排名、组内排名及每阶段清零。名次分（`place_points`，每桌名次形成的同分裁决键）按`+3/+1/-1/-3`累计，同分共享并列区间平均值，不能与总得分相加。[术语](../../UBIQUITOUS_LANGUAGE.md:89)、[阶段计划](../llm-guided-heuristic-route-2026-09-15/tools/sitin_stage.py:1401)、[组内计划](../llm-guided-heuristic-route-2026-09-15/tools/sitin_stage.py:1437)、[名次分实现](../llm-guided-heuristic-route-2026-09-15/tools/sitin_stage.py:1006)

| 阶段 | 建议主评判 | 同时保留 |
| --- | --- | --- |
| 海选 | 声明参赛人数、对手分布和赛程下的直接晋级达成率；尚无可信全场模型时，先以160单局阶段净分配对差筛候选 | 阶段总得分分布、低分尾部、名次分、参考晋级线距离；合成情景不得冒称真实海选概率 |
| 16强、8强 | 完整四人组160单局后的前二达成率 | 阶段净分差、第二名分差、名次分及同分未决比例 |

第三排序键白板获取数（`god_count`，阶段内发牌与牌墙摸得白板的官方统计）在现有离线工具中明确不可完整复现；不能用起手白数、最高持白或任意0填补。组内工具已有晋级识别区间：已知两键能确定前二则记确定成功／失败，跨晋级线并列则保留`[0,1]`。这类缺信息区间与抽样置信区间是两回事。[阶段账本](../llm-guided-heuristic-route-2026-09-15/tools/sitin_stage.py:1035)、[前二判定](../llm-guided-heuristic-route-2026-09-15/tools/sitin_stage.py:1086)

`competition`当前生产实现只计算单局结果的期望净分或达到显式单局分值的概率，没有完整阶段晋级模型；不得把研发阶段工具写成已接入线上目标。[当前效用边界](../../src/hangma_bot/competition/outcome_utility.py:10)

## 3. 现有能力与需要补充的评估

**模拟器能运行16单局完整桌赛，阶段汇总机制也存在；常用VIP自然开发批次仍限定8单局，需独立适配。** `TournamentConfig.rounds_per_game`允许正整数；模拟器依该值结束桌赛并延续真实庄权。阶段工具的`tables_per_group`可设10、`rounds_per_game`可设16；但其冻结对手白名单和旧候选准入不能直接冒充当前P0/RF1装配。应新增明确的评估声明及身份绑定，保留旧R8实验原件和语义。[配置](../../src/hangma_bot/kernel/config.py:64)、[完整桌赛结束](../../src/hangma_bot/simulation/engine.py:680)、[阶段配置](../llm-guided-heuristic-route-2026-09-15/tools/sitin_stage.py:617)、[旧面板白名单](../llm-guided-heuristic-route-2026-09-15/tools/sitin_stage.py:1907)、[VIP开发批R8约束](../../src/hangma_bot/offline/vip_route_development.py:143)

旧VIP运行配置在第346行仍硬建8单局，第756行分账分母也固定8；计划数量和实际数量须逐项审查，不能机械将所有`×8`改成`×16`，其中有些计数含对手池、换座和版本组合。最短装配复用现有`run_match_experiment`与唯一`SimulationEngine`，显式绑定当前策略、十桌种子、16单局配置、换座、阶段聚合及完整性检查。[配置装配](../../src/hangma_bot/offline/vip_route_development.py:346)、[分账分母](../../src/hangma_bot/offline/vip_route_development.py:756)、[完整配对执行](../../src/hangma_bot/offline/evaluate.py:1851)

另有一条时序边界：现有阶段账按串行桌序，逐桌注入此前已结束桌的积分。正式十桌并发时，不能令串行第2桌读取第1桌的最终成绩并称它是同一时刻真实可见榜单。第一轮只用当前可见手牌、庄闲和公开河／副露改牌效；赛后160单局聚合可以先做。以后若采用动态阶段排名，还须增加真实并发完成进度与榜单快照的建模。[阶段处境投影](../../src/hangma_bot/offline/evaluate.py:935)、[逐桌阶段账](../llm-guided-heuristic-route-2026-09-15/tools/sitin_stage.py:1970)

| 指标 | 现状与补充要求 |
| --- | --- |
| 胡牌收入、四倍及以上收入、支付、净分 | 已有冻结四座复算和自然结算分账，可复用；按起手白数×庄闲及版本分层。起手多白不等于四倍以上胡，两者须分开 |
| 庄付闲、闲付庄、闲付闲 | 已有支付次数、金额、每单局和每次支付统计；保留总量与频率，不能只比较单次金额 |
| 首听速度、听后转胡、首次听口宽度 | 测试赛已有轨迹重建，月内自由赛广池还只测得普通摸牌机会内早胡；需要把轨迹指标接入新160评估，使用唯一规则数学，并同时记录未听／未胡单局 |
| 无白／单白防守、庄上防守与抢庄 | 从完整顺序可补两类白数×庄闲：庄家本人／闲家先胡、庄付闲、胡与流局保庄；闲家本人／庄家先胡、两类支付、尚有后续单局时的抢庄及实际后续得失。不能只按少付或庄权频率声称增强 |
| 公开进张容量与合法胡资格 | 区分公开未见容量、真正墙内牌数和合法胡出口；只有前者及规则允许的条件分析可输入线上。固定终点也要看听后危险资格限制，而非仅结构向听0 |

收入和支付现实现见[自由赛统计](./free_analyze.py:26)；测试赛轨迹指标见[重建与首听提取](./test_oct8_analysis.py:182)、[统计字段](./test_oct8_analysis.py:40)。“公开宽度不足”暂不是既有事实：测试赛单白闲家首听活牌码种为4.71对4.27、公开容量14.68对13.73，粗指标并不窄。应测早段达到低向听时的容量、实际合法出口与胡牌竞争，而非先认定加宽一个参数就能补回失分。[测试赛速度与宽度解释](./test-oct8.md)

## 4. 稀有与低效并不直接等于小价值

**最新范围是无白／单白攻守与多白保护；改善价值须看“频率×可改幅度×积分影响”。** 下表仅把冻结P0起手暴露比例折算至160单局，供理解研究覆盖，不是正式阶段概率或增益预测。[实际分账](./free-results.json)、[P0报告](./REPORT.md:44)

| 起手白数 | P0单局数／占比 | 160单局观察比例折算 | 冻结P0收入／支付／净分 |
| --- | --- | ---: | --- |
| 无白 | 2,784／66.92% | 107.08 | 8,398／14,649／−6,251 |
| 单白 | 1,177／28.29% | 45.27 | 9,966／4,532／+5,434 |
| 双白以上 | 199／4.78% | 7.65 | 3,470／436／+3,034 |

多白只有4.78%暴露，却贡献15.89%胡牌收入；S03也仅4.65%暴露、贡献14.07%收入。因此可以停止将新增研发主要压在稀有多白上，但应保护已有抓机会能力，不能取消多白回归。本次测试赛11个多白单局净+217，其中两次胡牌贡献120收入，亦提示短阶段的尾部机会会显著改变排序。

无白基础成型慢也不能推出增益小：若无白每单局实际改善0.5分，仅算术换算即约53.5分／160单局阶段；同样每单白单局改善0.5分约22.6分。它们不是已证增益，也不包含连庄改变后续庄闲暴露的影响。本轮无白同样实际开发成型、形状、胡牌兑现及防守，不再仅列通用保底。

## 5. 工作安排补正与难度

**具体执行统一按[最新工作计划](./SINGLEWHITE-160-WORKPLAN.md)：** 多白机会保护，两类白数画像与基础候选，共同防守、庄上防守与抢庄扩展均有任务和标准。基础候选对基线，扩展对冻结牌效父版，并检验最终版对原基线。离线起手分组与线上当前持白分开；分账不独自承担因果归因。160单局阶段用于调参及独立确认，冻结搜索范围、预算与确认门，开发未知和已证负效分开，对手池与模拟误差单独讨论。

原“基线”角色现已拆清：RF1拟作研发父版，P0 approved-v4作正式参赛参照，最终效果须对后者。先做首算子活动、保护和装配，再有限先导交付真实数值声明；全画像累积完成，两臂不互相阻塞。初筛、开发投资判断和未曝光确认不混为一门。

| 工作 | 实现难度 | 实际难点 |
| --- | --- | --- |
| 多白保护、无白／单白基础候选 | 小到中 | 除当窗保持父版外，还须检查跨白数后续影响，核算两类的真实阶段贡献 |
| 两类白数时序画像 | 中 | 把成型、结构听牌与条件出口、竞争兑现分开，不以粗宽度增加代替效果 |
| 无白／单白防守与庄闲有界调价 | 中 | 已有牌效、座位与公开结构输入；主要难在快听却难胡、过量副露、抢庄代价及多白保护 |
| 160阶段协议、当前版本装配、分层轨迹与前二汇总 | 中 | R8固定开发入口、旧白名单、完整阶段配对、各指标分母与并发时序需要明确处理；不需另造规则引擎 |
| 校准的庄家听牌模型、精确连庄后续／阶段价值 | 大 | 需要合法公开历史、独立标签与留出验证；隐藏信息权限、竞争截尾和剩余机会均难，第一轮不以此为前提 |

验证顺序：先检查实际改选及普通成功／失败、多白与无白负控，随后做新的完整R16同牌山换座；主门比较多个独立160单局阶段净分与相应晋级目标，分账确认增益来自收入还是少付。规则一致性、合法保底、动作时限、故障降级和正式／测试赛事配置包及生命周期回归继续有效。不得用一次160单局正分或某个定向病例改善授予发布；按现行验收口径不额外要求官方现场赛事为候选上线门禁。[现行验收](../vip-route-2026-09-30/evidence/t192-targeted-followup-1/ACCEPTANCE-POLICY.md)
