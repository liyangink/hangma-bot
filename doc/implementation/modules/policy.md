## 交付结果

实现确定性的 `WeightedHeuristicPolicy` 与只保留紧急动作的 `SafeFallbackPolicy`。输出完整 `DecisionPlan`，不执行提交。

MVP 后续按[三个候选版本计划](../policy-iteration-plan.md)实施。当前保留 `weighted_heuristic` 为 V0；新增可选 `weighted_heuristic_v1`，分别使用独立的评分和权重源码，不影响并行调用方。V1 排序以 [接口协议 §4.2](../interface-contracts.md#42-v1-策略排序语义2026-09-05)为准：合法胡、可信候选、未知候选；全部未知时紧急候选优先。`rank` 是执行顺序，跨层不能按总分重排。

V1 的固定参数、未知降级、数值失败和真实时限测试见[实施验收记录](../reviews/policy-v1-implementation-2026-09-05.md)。响应 Pass 已提供新等待事实；V0 装配使用 `LegacyWeightedHeuristicPolicy`，测试房鸣牌策略使用 `LegacyClaimIfLegalPolicy`，两者只适配输入而不改变冻结源码。新事实与旧版消费边界以[接口协议 §4.3](../interface-contracts.md#43-响应过牌的等待事实与冻结策略兼容2026-09-06)为准。

## 第一阶段排序设计记录（不是 V1 执行规范）

向听与有效牌数学只存在于 `hangma`（接口协议 §4.1 候选牌效事实）。`policy` 消费 `RuleCandidate.facts`（`CandidateFacts`）并加权，不重新推演手牌合法性、向听或有效牌。分层规则：

1. 官方规则允许且当前应当胡的动作（`fact_kind=WIN` 置顶）；
2. 硬规则和抓打圈约束（规则候选合法性已表达）；
3. `facts.shanten_after` 最低者优先（吃/碰按最佳后续弃牌后的等待状态）；
4. `facts.useful_tiles` 加权剩余张数最大者优先；
5. 财神保留（基于观察与事实组合，不重算向听）；
6. 熟张与喂牌风险（公开牌河口径）、吃/碰/杠风险与收益（鸣牌仅在鸣后即听牌且有效牌收益覆盖风险时胜过过——`pass` 属 `NOT_APPLICABLE`、无现手牌基线，保守方向是契约直接推论）；
7. 桌内积分、剩余单局和当前名次只做保守风格调整。

`facts=None`（紧急路径或未覆盖动作族）按未知处理，给中性分。杭麻没有点炮胡时，防守分主要衡量弃牌是否帮助下家吃、他家碰、庄家或直接名次竞争者提速。不要照搬日麻放铳危险度。

## 降级规则

- 先从 `RuleAnalysis.emergency_candidate` 构造保底计划。
- 主策略超时、异常、空计划、重复候选、引用规则集外动作或已拒绝动作时，应用层使用保底计划。
- 明确 409 拒绝后重新调用策略，`decision_id` 不变、`revision` 增加、已拒绝动作必须排除。
- 第一阶段不接入 LLM、模拟器或价值网络。

## 完成定义

- 同输入同配置结果逐字节可复现。
- 每个候选有总分、分项和中文可读原因。
- 所有规则候选均出现在排序或有明确过滤原因；紧急候选不被普通 Top-K 删除。
- 1 秒窗口基准和异常回退契约测试通过。

## 2026-09-15 启发式候选装载接缝

新增 `heuristic_adapter.py` 与 `heuristics/` 子包，作为**离线生成候选**的唯一装载路径。候选是独立模块，经 `heuristics/__init__.py` 的**静态字面量注册表**装载；适配器只在 `evaluation_v2.score_candidates` 之后追加一个按 `scope` 生效、受 `bound` 约束、越界写审计说明的分项，**不复制** V2 的过滤、可信层级、排序、紧急保底与截止时间检查。`adjustments=()` 时行为逐字节等于基线（构造保证）。

参数经 `weights` 的 `adj.` 前缀传入；候选身份 = 模块 + 有效参数 + 源码指纹，参数或源码一改即失效。候选不得声明合法性、不得重排、不得读时间/随机/文件、不得做搜索；源码指纹不在本包内计算（本包禁止文件 IO）。评分上下文新增四个规则状态字段，见[接口协议 §4.8](../interface-contracts.md)。

**上线边界**：这条接缝只负责“能插进来”，“准不准插”由三道门禁、契约测试与人工审核决定；线上仍只有确定性启发式，不含任何 LLM 调用。
