# 有界等胡升级候选 v1

本候选比较“现在胡”与“保持等待，下一次自摸胡”的分值及风险。配置名为 `hu_upgrade_v1`，仅在离线评估入口显式装配，真实运行默认仍为 V2。它继承 `one_draw_value_v1` 的普通听牌排序，进一步处理已经可以胡的升级机会。

## 1. 决策边界

仅当规则模块已给出完整的普通摸牌爆头见证，且各互斥进张的最低本人净分都高于立即胡时，才比较升级弃牌。普通摸牌的 `ValueConditions.baotou` 由规则模块对摸前手牌作任意进张检查得到；策略不重算胡牌、不用未见牌数代替摸牌概率，也不把杠补进张移到不杠分支。

设立即胡净得分为 G，下一次普通自摸的最低净得分为 U，校准的生存下侧估计为 p，无条件平均支付上侧估计为 c（单位为 G 的倍数）。候选使用 `p×U−c×G`，必须严格大于 `1.10×G` 才等待。c 已包含等待失败的频率，不能再乘一次 `1−p`。

最低分值只在“弃牌生效、没有别人先结束单局、保持摸前手牌、得到下一次普通摸牌”条件下成立。响应窗口已有可信爆头等待时选择合法 Pass，保持这些前提。下一摸重新决策；若再次飘白，是另一次有界比较，不能预先累加多次飘的分值。立即胡始终保留为后续候选；缺证据、空校准表、未覆盖分组、观察异常或增强失败时沿用完整基线。

## 2. 风险证据与限制

风险表不是官方规则。规则依据继续使用 v23 / 2026-09-08 的官方金例及 `fan-calc` 对拍；本次没有改变 C/Python 牌型算法或结算实现。

校准使用 512 个独立根种子，各跑一个八单局完整桌赛。四家均为冻结 V2；遇到可升级 Hu 时，从不透明世界经模拟器公开方法分叉。分支先执行升级弃牌，本人只过牌并在下一摸立即胡，其他人继续 V2。原桌赛继续原来的立即胡，分叉不改变后续原桌赛。未来牌和结果仅用作离线标签，不进入 `DecisionRequest`。

764 个分支全部完成，分组只使用当前快照的剩余牌数、对手最后弃牌和公开副露。剩余牌数包括 20 张保留区；有对手最后一弃为白或至少三副公开副露时归入高威胁组。每组至少需要 50 个独立根、100 个机会；按完整桌赛根种子聚类重采样 10,000 次，分别取生存比例 2.5% 分位和无条件支付 97.5% 分位，再向保守方向取两位小数。生存比例最高取 0.95，支付倍数最低取 0.10。

## 3. 模块与审计

`HuUpgradePolicy` 先取得完整 `OneDrawValuePolicy` 计划，再进行有界比较。规则、观察、策略及审计载荷的公开契约均不变；没有新增线上模型或模拟调用。风险表由离线显式组合入口注入，策略无网络、磁盘或世界状态访问。`upgrade_weight=0` 精确回到一次摸牌候选。

`DecisionPlan` 保留基线评分分项、排序和紧急候选身份；改变首选时追加成功分值、无条件支付、校准版本与决策门槛。消费者按 rank 执行，不能拿立即胡旧评分与升级净分跨层重排。增强异常保留已经完成的完整基线，取消始终向上传播。

离线清单保存实际风险表、版本、开关和安全余量。研究运行器的旁路审计只读取策略已经收到的观察及完成后的公开单局结算，检查每次等待是否保持手牌、下一摸是否仍有合法胡，以及可胡分值是否至少达到原条件下界；旁路标签不反馈策略。

## 4. 固定验证方案

校准种子 910000–910511，开发种子 920000–920031，V2 主确认种子 930000–930127，一次摸牌候选消融确认种子 940000–940063，彼此分离，也不复用上一版的开发/确认种子。每个效果评估根包含两版本各四次换座，每桌八单局，四种逻辑初始庄家按根等量。

主要指标为完整桌赛净增积分，按根种子计算配对差值和置信区间。补充独占第一比例、胡牌频率、番数分布、总胡牌进分、总支付及等待校准误差。不得把单个最高分值、重复等待机会或中途有利分组当作整体改进证据。逻辑时钟实验验证策略取舍；真实 CPU 耗时与 1/3 秒窗口另测，完整真实运行还需要后续测试房及发布审核。
