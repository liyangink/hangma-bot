# 模型训练与赛事目标评估启动计划

日期：2026-09-11。状态：启动方案及本机准备度核查；S0 最小共享代码已实现，具体冻结范围见 [outcome-v1](./model-competition-contract-v1.md)。尚未开始正式网络训练。

## 1. 目标与决定

**停止继续扩展当前启发式候选，把研发主线转为候选结果模型和赛事目标评估两条并行工作线。**启发式保留为对照、初始续打策略和线上合法保底。近期交付一个能够复现训练、装载推理、连续决策并完成完整桌赛评估的模型候选；不把训练损失下降当成策略达标。

候选结果模型（`CandidateOutcomeModel`，根据玩家可见信息和候选动作预测本单局的四家积分结果）回答“动作之后可能发生什么”。`competition` 回答“这些结果对当前赛事目标有多大价值”。`policy` 汇总两者并选择动作，对外仍只提供 `BotPolicy.choose(DecisionRequest, DecisionBudget)`。

这延续[主技术方案 §6.3—6.5](../hangma-ai-bot-technical-plan.md)，本批实际交付以 [outcome-v1](./model-competition-contract-v1.md) 为准。现有启发式具体候选没有证明显著改进，足以支持停止这一批探索；不等于已经证明所有启发式不可能改进，也不预先保证模型有效。证据见[探索收尾](notes/heuristic-research-closeout-2026-09-11.md)。

本批沿用正式赛关闭 `YouCaiBiKao` 的用户约束，不将其列为专项优化或数据覆盖目标。

**已有可用的规则、模拟与研究底座，尚无可直接发布的模型训练链路。**以下区分本机核验和报告记载。

| 项目 | 2026-09-11 核查结果 | 启动时如何处理 |
| --- | --- | --- |

| 正式赛事目标模块 | `src/hangma_bot` 尚无 `competition`；目标意图、事实质量及接入已有方案 | 由赛事线按真实消费者落最小实现，不能把提案当作已交付 |

| 历史规则分层 | 上述 development/confirmation 使用旧庄家推进源码；confirmation-fixed 已修正。三个包的规则字符串相同而源码哈希不同 | 按代码和规则证据判兼容；旧包排除正式训练/确认，修后包也不能自动成为新模型独立留出 |
| 主线并行修改 | 六份架构、术语、接口和赛事方案存在其他工作的未提交修改 | 本文独立新增；共享文件由集成人收口后提交，不将他人改动打包提交 |

本机旧导出器位于 `.team-work/big-hand-paths/review/heuristic-balanced-2026-09-10/export_decision_dataset.py`，属于本地研究证据；主线可携带的依据为[庄家推进](../../src/hangma_bot/hangma/progression.py)及[最新候选标签说明](notes/candidate-outcome-labels-evidence-2026-09-11.md)。

**最新数据交接不是整个项目的等待条件。**模型线可先实现编码与小批自然模拟标签采集；若研究产物暂不可取得，复用模拟器公开接口重新生成最小训练批次，并如实登记与报告数据的区别。赛事线使用人工榜单和确定结算立即开发。

## 3. 分工与共享接入

**两条算法线，加一个负责公共契约与集成的角色。**集成人是文件归属和交付责任，不需要再开一条独立算法线。

| 工作包 | 所有权与交付 | 不依赖什么 |
| --- | --- | --- |
| 共享接入 | 最小结果类型、身份和版本语义、预算/降级、codec、真实生产者/消费者契约用例；统一修改 `kernel`、`policy` 入口、`bootstrap`、审计及离线驱动等共享文件 | 不等待网络结构定型；不预建模型注册平台、通用消息总线或尚无消费者的字段 |
| 模型线 | `learning` 的共享编码、模型定义、校准与制品校验；`offline` 的标签采集、训练、预测与完整桌赛评估；模型候选策略的独立实现文件 | 不等待赛事目标算法，也不等待阶段续局模型或真实测试房 |
| 赛事线 | `competition` 的赛制目标、排名事实校验、参考追分与适用性；人工榜单/公开结算的情景评估；与 `policy` 的可选接入 | 不等待训练好的模型；以确定结果或声明为人工的结果分布验证计算 |

公共提交形成后，两线分别从该提交建立 `codex/model-outcomes-v1`、`codex/competition-utility-v1` 独立分支和工作区。各自固定依赖、配置和产物路径；主线并发修复需显式同步。不能用两个工作区修改同一套未提交共享类型。

### 3.1 先冻结语义和可执行样例

**复用已存在的 `PlayerObservation`、合法候选和 `choose`，只补本批真实接触面。**下表是收口要求，不代表已经存在这些类型。

| 接触面 | 首批必须固定的内容 |
| --- | --- |
| 观察与候选身份 | 观察版本及权威序号、`action_key`、合法候选来源；候选排序变化不得错配模型输出 |
| 预测终点和单位 | 从应用候选首动作前的决策时刻，到当前单局结束的桌内积分变化；包含本人未胡、他家胡和流局；不包含后续单局 |
| 四家结果 | 按物理座位 0、1、2、3；编码可在内部按本人旋转，输出必须逆变换；样本与预测校验积分守恒 |
| 模型能力 | 条件均值、联合积分分布必须分型；均值输出不能被当作概率分布，四个独立边际也不能当作联合分布 |
| 结果适用条件 | 规则、代码、特征/动作编码、数据、续打策略、对手池和校准版本；观察绑定及可用/缺失/失效原因 |
| 赛事输出 | 目标、适用阶段、事实来源与质量、未知语义；目标效用不冒充实际积分或已校准晋级概率 |
| 预算和失败 | 先有合法保底；原预算不延长；模型缺失、错误版本、非法数值或来不及推理时显式回退并审计；预算以单调时钟秒计 |

契约交付至少有一个真实生产者和消费者、样例、编码解码及旧记录兼容测试。先用小批数据跑出的简单估计器验证接口，再替换模型内部；没有真实产出的分布类型继续保持提案状态。只写字段表或空 `Protocol` 不算完成。

`learning` 不依赖 `competition`，`competition` 不读取网络或模型文件。若两者交换结果，稳定值对象由共享契约承载；`policy` 消费双方，装配和加载通过唯一组合根注入。训练入口属于 `offline`，线上不得导入训练任务。

### 3.2 两线如何独立验收、再组合

**模型线先按期望净分检验，赛事线先检验目标计算，组合后再检验真实赛事决策。**

完整目标是四家联合结果分布。第一项工程里程碑允许用明确声明为“条件均值”的小模型跑通数据、训练、推理、降级和完整桌赛链路；保留全部原始联合积分标签。均值版本只能支持相应的线性期望积分目标。需要追分门槛、尾部风险或名次概率时，再消费经过验证的联合分布，不能从均值虚构这些概率。

赛事线先实现排名顺序、可信事实、目标意图和未知回退，用规则已知结算及人工情景验证。可以用冻结启发式做独立的目标策略实验，但不继续无界搜索启发式参数，也不将该实验视为模型接入的前置条件。

目标权重、模型估计和启发式分数不同量纲，不直接相加；赛事效用只能应用一次。首版阶段续局模型（`StageContinuationModel`，根据固定四人小组的阶段账本和进度预测阶段结束排序）后置，不把本单局预测误称为整阶段晋级预测。

赛事模块通过契约和情景验收后可以先合入主线的可选能力；启用新的线上动作策略还需完整组合评测与人工发布审核。合入代码、证明提高赛事指标、切换线上默认是三个不同动作。

## 4. 模型线的第一条实际路径

**先完整可见编码和小型监督学习，再做新策略续打的数据迭代。**不重复把少量手工特征加权作为研发主线，不直接训练一个把不同赛事目标混在一起的动作分类器。

1. **收口数据来源。**获取最新研究提交与 manifest，核验规则和采样/分叉代码；所有已经用于研究判断的牌山登记为已用。拿不到该批也可立即从自然模拟采集小批。
2. **实现共享编码。**同一编码器处理手牌、完整公开副露、牌河、公开动作历史、规则状态、本人/庄家相对关系与合法候选。网络训练和推理共用；规则牌效事实只消费 `hangma` 的结果。明确历史截断和缺失掩码，不以空数组伪装完整信息。
3. **生成逐候选结果标签。**在看结局前固定窗口与候选抽样；从同一完整世界对候选应用首动作后续打至本单局结束。每个座位的续打策略只读自己的合法观察。保存原始四家积分，不把单世界事后最佳动作直接当学生最优动作标签。
4. **跑通首个模型。**使用完整观察编码和小型非线性网络，与已有线性/规则特征估计比较；首批先测标签吞吐、训练耗时、内存和批量推理耗时，再决定数据规模与硬件。输出均值时明确声明能力，不提前包装成分布模型。
5. **验证持续改选。**固定模型后，在完整桌赛里每次决策都允许模型改选，与稳定基线同牌山、换座位比较。一次改动作后用旧策略续打的标签效果不是这一项证据。
6. **迭代数据与联合分布。**根据误差、覆盖和完整桌赛结果补新策略访问的局面、续打策略与对手池，再扩展分布输出和校准。不能靠反复检查同一留出集调参。

先不把完整隐藏世界后验采样器、在线多世界搜索、大模型或强化学习训练平台设为阻塞条件。自然模拟可产生监督标签；适用条件见[标签数学与证据](notes/candidate-outcome-labels-evidence-2026-09-11.md)。

这与 [Suphx 原论文](https://arxiv.org/abs/2003.13590)区分可见决策信息、训练辅助信息和长期结果的思路相容，但不是照搬其日麻训练流程，更不构成杭麻提升的证明。先完成监督结果模型，是基于本项目当前已有底座和可控验收成本的工程选择。

## 5. 评估设计与验收

**完整桌赛效果决定是否值得上线；预测误差、校准和特殊手牌案例负责解释结果。**

| 层级 | 必须交付的证据 |
| --- | --- |
| 数据 | manifest/源码可追溯；候选首动作与终点正确；四家结算守恒；异常单独登记；同牌山、换座、候选分支和续打变体归入同一划分组 |
| 信息权限 | 完整世界和教师结果只用于标签；种子、参与者标识、未来牌墙不入特征；同一玩家观察在不同隐藏世界下编码一致 |
| 预测 | 独立开发验证划分；按本人/庄家相对关系、白板、特殊胡牌、动作族与对手池分层；均值误差或分布校准与其能力声明一致 |
| 策略 | 按运行 `config.Rounds` 完成桌赛，同牌山换座；事先冻结主要指标、对手池和样本量/顺序检验规则；按完整桌赛或牌山根聚类计算区间 |
| 赛事 | 赛事线的人工榜单闭环与真实阶段格式分开；记录无条件目标达成、净积分、失分尾部和榜单事实失效，不只筛选成功案例 |
| 运行 | 覆盖实际 1 秒/3 秒窗口、全候选批量推理、并发资源竞争、模型缺失/失效/超时与审计；规则分析与推理都计入原预算 |

已用于历史研究和参数选择的确认集，不再作为新模型最终独立留出。包括报告记载的 96 个牌山根，应登记用途；新候选冻结后使用未参与开发的新牌山与另一个对手池确认。

期望积分目标可能受少数大分影响，需报告置信区间、尾部贡献和跨独立批次的稳健性。中位数和正分比例是辅助诊断，不能擅自代替预先声明的期望积分目标；也不能因为分布尾部较重就把全部改进称作无效信号。

首个工程验收为：**一批可追溯候选样本 → 共享编码 → 可复现训练 → 带版本的模型制品 → 离线批量推理 → 连续完整桌赛 → 故障降级审计。**这一闭环通过时称“模型管线可用”，尚不称“强度超过基线”。

## 6. 执行顺序和停止条件

**先一个小型共享提交，随后两线独立推进；不把数据交接或赛事模型成熟当成无限等待理由。**

| 顺序 | 具体产物 | 完成后推进 |
| --- | --- | --- |
| S0 | 数据交接清单、固定起点、实际输入输出样例、最小生产类型/消费者与契约测试；协调当前六份未提交文档 | 发布共同提交，建立两线工作区；内部编码/算法原型可同时开展 |
| M1 / C1 | M1：编码、最小自然模拟标签采集、版本化数据；C1：排名和事实质量、目标意图、人工结算情景 | 各线按自己的用例验证，不互等 |
| M2 / C2 | M2：首个训练—制品—推理—桌赛闭环；C2：可信赛事上下文与离线榜单更新闭环、关闭/失效回退 | 各自提交可选能力；固定共享文件由集成人合并 |
| I1 | 模型结果与赛事目标只组合一次；按能力限制支持目标，补组合审计与独立确认 | 形成可审查候选，开展真实运行验证 |
| 发布 | 完整指标与可靠性门禁通过，人工审核配置与版本 | 显式启用，稳定基线继续保留 |

当前不需要用户新建测试房。真实测试房用于候选完成后验证协议、并发、时限、恢复与赛后审计；大批训练标签和受控策略强度比较由本地模拟主动产生。

若完整编码的小模型仍没有可信改善，先区分数据覆盖、标签噪声、续打偏差、预测能力和持续决策分布变化；据此决定补样本、分布建模或进入强化学习。只有证据表明当前路线在可用算力/时限内无法继续、需要外部资源或目标发生方向变化时才暂停调整计划。

随后按用户授权完成 S0 最小共享实现：结果值对象、经验表生产器、单局目标计算、策略装配和审计往返。它是后续两线的共同代码起点；自动赛事事实与网络训练尚未交付，也未创建两条正式开发分支或替换线上策略。表中历史准备度描述保留核查时点，最新实现以 [共享契约](./model-competition-contract-v1.md) 为准。
