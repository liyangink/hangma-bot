# 启发式策略迭代计划

> 负责人：当前主审；先分析和候选设计，等审计/模拟/评估可用后验证。源码证据基线 `c17ce06`；本次不修改线上策略，也不声称强度已提高。

## 1. 当前结论

修复后的 adapter/rule 已通过所述测试房间验收，但验收策略是 claim_if_legal。这证明相应环境下动作与协议可运行，不能据此认定 WeightedHeuristicPolicy 已经过强度验证。优先检查动作族之间的评分可比性，再做局势相关调整，最后探索赛事效用。

现有实现入口是 `policy/weighted_heuristic.py`，评分在 `policy/evaluation.py`，参数在 `policy/weights.py`；牌效事实由 `hangma/candidate_facts.py` 唯一提供。BotPolicy 接口保持不变。

## 2. 已观察事实与待验证假设

| 顺序 | 源码事实 | 假设和下一步证据 |
| --- | --- | --- |
| H1 | Pass 的 NOT_APPLICABLE 牌效项为 0；吃碰等 HAND_PROGRESS 含 `-100×向听+有效牌`，再扣鸣牌风险 | 不同动作族可能用不同基准，导致过牌被系统性偏好。先采集有实际改善的吃碰/过局面，比较可比牌效；不是证明所有过牌错误 |
| H2 | 所有杠固定加 40，规则 facts 标记补牌未知；打财神固定扣 60 | 局末/牌墙少/特殊链/对手节奏下固定分值可能偏离期望桌内积分。先按局势分组分析，再做消融 |
| H3 | safe_codes 只看他家牌河出现过的牌；风险用靠近下家/庄家副露近似 | “熟张”只是启发信号，不是杭麻规则安全证明。分析真实鸣牌、牌墙剩余及目标座位暴露后再调整权重 |
| H4 | 名次调整只读 observation.scores 的桌内名次；评分未消费 request.competition | 当前不是赛事晋级目标策略。先明确自由赛与测试赛事分别实际能提供什么事实，不能用桌内第一代替海选晋级 |
| H5 | 立即胡牌默认加 1000；flexibility 字段保留但未使用 | 保留立即胡的稳定基线，先处理排序口径。不得因为存在收益模型设想就开始无证据弃胡 |

H1 的说明性算例：若吃碰后的向听为 1、有效牌剩余估计 20、碰风险 6，忽略两者共有项时碰的相关得分为 -86，而 Pass 相关项为 0。这个算例揭示比较基准，不能证明该具体碰动作比等待更好；必须取得 Pass 当前牌效和后续真实评估。

## 3. 分阶段实施

P1 在现有公开类型下建立候选审查集和评分差异报告，固定 c17ce06 对应完整权重为启发式基线。claim_if_legal/safe_fallback 是合法性与可靠性参照，不能偷换成唯一强度对手。

P2 优先解决已证实的评分可比性问题。若需要 Pass 的当前牌效，由 hangma 生产与动作后事实可比的数据，作为独立受控行为变更登记；policy 不实现第二套向听。模拟线正在补规则推进期间，主审排定规则文件修改窗口，避免两个分支同时修改 candidate_facts。

P3 在足够案例支持后逐项加入可见局势因素：剩余单局数与桌内分差、牌墙剩余、本人牌效、庄家、公开副露和特殊链。每次只引入一类有解释的变化，保留配置开关、score_parts 与确定排序。首先做固定决策集的解释/合法性/耗时检查，完成候选实现后等待真实模拟评估，不先上线试猜。

P4 模拟器规则对拍通过后，用完整桌赛、同牌山、换座位及固定对手池检验候选；审计能关联异常后，再做测试房间 M>1 及自动匹配外部对手验证。模拟效果与线上可靠性分开报告，采数环境不自动替代发布门禁。

P5 增加赛事效用时才创建有真实逻辑的 competition 模块。只把缓存 CompetitionContext 的权威事实转换为目标，缺晋级规模/排名更新时间/阶段事实时降级到桌赛目标；不得新增实时 HTTP 到策略中。自由赛门户榜单缺失不会阻塞牌局策略，但会限制可声称的赛事指标。

## 4. 训练衔接

审计/模拟/评估是训练前的公共基础，不保证仅靠官方数据就能直接训练两个模型。

- 候选结果模型需要模拟展开或可靠终局生成标签；输入严格来自玩家观察与候选。只记录实际动作不能提供所有反事实候选的真实标签。
- 阶段续局模型还需要完整赛事格式、对手分布、阶段结果与排名口径；完整桌赛模拟器不自动具备阶段模拟能力。
- 创建 learning 时统一观察/动作编码和训练推理网络；训练集按 split_group_id 分离，记录规则、特征、动作、续打策略、对手池、采样器/校准及种子版本。缺采样/校准阶段显式写 not_applicable，不伪造版本。

本线交付候选改动说明、可审计评分差异、固定决策检查及完整比赛报告。只有统计与可靠性门禁支持，才建议切换稳定版本；“候选代码完成”和“证明效果提高”分别报告。
