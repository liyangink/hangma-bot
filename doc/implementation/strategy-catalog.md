# 可用策略枚举与选用说明

**正常自由赛和赛事沿用 `weighted_heuristic_v2`，并在配置中显式填写。**常用模板已选择V2，但省略 `strategy` 时，代码默认仍为旧版 `weighted_heuristic`；两者不能混称。本文只整理现有可用值，不变更默认配置或发布候选。

核对日期：2026-09-09。主线基准为 `a8c5df9`，实验分支为 `codex/v2-hu-upgrade`（等胡源码及校准提交 `1305b2c`；续飘候选见下表专项记录）。下表“实验分支”表示这些值尚未合入上述主线；复制配置不会自动取得对应实现。

## 1. 默认值与生效优先级

| 使用情形 | 生效策略 | 依据 |
| --- | --- | --- |
| 自由赛示例配置 | `weighted_heuristic_v2` | [auto-match.example.json](../../configs/auto-match.example.json)显式设置 |
| 单身份赛事示例配置 | `weighted_heuristic_v2` | [participant.example.json](../../configs/participant.example.json)显式设置 |
| 通用测试房示例配置 | `weighted_heuristic_v2` | [test-room.example.json](../../configs/test-room.example.json)显式设置 |
| 单身份配置省略 `strategy` | `weighted_heuristic`（V0） | [组合根](../../src/hangma_bot/bootstrap.py)的 `DEFAULT_STRATEGY` |
| 测试房顶层也省略 `strategy` | `weighted_heuristic`（V0） | [测试房加载器](../../scripts/run_test_room.py)的缺省值 |
| 四身份测试房指定 `identities[i].strategy` | 该身份策略覆盖顶层策略 | 未指定的身份继承顶层；各进程启动时固定 |
| 离线评估 | 实验JSON各项声明的 `name` | 没有自动选择线上默认的行为 |

运行时以启动输出的“策略”和审计清单中的 `policy_version` 为准；实验还须核对 `policy_weights.risk_version`、规则版本及分值分析开关。历史房间专用配置可能仍显式选V0或探针，不能因新模板是V2就推定历史会话也用了V2。

## 2. 全部可用值

“线上入口”包含自由赛 `auto_match`、测试赛事 `test_tournament`、正式赛事 `official_tournament` 和测试房 `test_room`。“支持”仅说明装配器接受，不等于已通过策略强度或赛事发布门禁。离线栏指 `scripts/evaluate.py` 的策略装配，分值候选的完整效果比较还须遵守下一节限制。

| 枚举字符串 | 可取得版本 | 线上入口 | 离线评估 | 行为简介与用途 |
| --- | --- | --- | --- | --- |
| `weighted_heuristic` | 主线、实验分支 | 全部；**省略配置时默认** | 支持 | 冻结V0，基础加权评分；过牌事实使用旧兼容视图。用于历史基线复现，名字不是“自动选择最新启发式” |
| `weighted_heuristic_v1` | 主线、实验分支 | 全部 | 支持 | V1可靠排序：合法胡优先，可信评分和未知事实分层，保留紧急候选。历史对照用 |
| `weighted_heuristic_v2` | 主线、实验分支 | 全部；**常用模板选择** | 支持 | V1基础上统一过牌与吃碰后的等待牌效比较；缺可信过牌基线时保守退路。当前稳定选用值，普通决策仍以牌效评分为主 |
| `weighted_heuristic_v2_white_guard` | 主线、实验分支 | 全部 | 支持 | V2加普通弃财保护：非爆头且有其他未拒合法弃牌时不主动弃白。爆头、强制弃白或没有替代时保留原路；可选保护变体，**不是默认V2的别名** |
| `safe_fallback` | 主线、实验分支 | 全部 | 支持 | 只使用规则提供的紧急候选，不作增强评分。用于保底与诊断，不作为争取高积分的常规策略 |
| `claim_if_legal` | 主线、实验分支 | 解析器接受全部；用途限测试验收 | 不支持 | V0派生的主动鸣牌探针，便于获得吃碰杠提交证据；不是“所有合法动作都执行”，不用于策略强度比较 |
| `catch_play_probe` | 主线、实验分支 | **仅测试房** | 不支持 | V2派生的抓打圈探针，主动优先合法弃白、吃碰和明杠；弃白可排在胡前。用于规则取证，分数不能代表V2实力 |
| `one_draw_value_v1` | **仅实验分支** | 不支持 | 支持 | V2底座；V2首选已听牌时，对可比较的普通等待候选按 `Σ(未见张数×条件胡牌净分)` 重排。涉及弃牌、过牌及吃碰后的指定弃牌路线；不越过杠的位置，立即胡保持优先。旧规则评估未证明显著提升 |
| `hu_upgrade_v1` | **仅实验分支** | 不支持 | 支持 | **一次摸牌分值排序＋有界等胡升级**。保留上一行普通排序，再增加下面的等胡逻辑；不能用V2底座候选的确认结果宣称这个组合已提升 |
| `v2_hu_upgrade_v1` | **仅实验分支** | **仅测试房** | 支持 | **V2＋有界等胡升级**，即当前复验候选；普通弃牌不使用一次摸牌分值排序。v10独立确认每桌净分差+4.336，95%区间[+1.914,+7.398]，限V2模拟对手池；未达到预登记替换门槛，未发布 |

| `v2_claim_piao_v1` | **仅实验分支** | 不支持 | 支持 | V2＋已财飘、吃碰后无立即胡时的条件续白排序；两路须完整任意听、支持集相同且续白条件分值严格占优。新开发256桌赛未触发增量，净分差0；**停止独立确认，仅保留研究复现，不推荐替换V2** |

字符串 `v2_hu_upgrade_v1` 表示算法身份；当前风险参数版本是 **`hu-upgrade-risk-v2-v10`**，两者的版本号用途不同。`c_grouped`、`python_grouped` 是规则数学后端，不是策略枚举；`YouCaiBiKao` 是赛局规则开关，也不是策略名。

真实装配来源：[线上策略与模式门禁](../../src/hangma_bot/bootstrap.py)、[测试房策略继承](../../scripts/run_test_room.py)、[离线策略装配](../../scripts/evaluate.py)。策略实现不在本表建立第二份注册表；新增、改名、改变模式范围或默认值时应同步此表及运行模板。

## 3. 当前等胡候选相对V2的改动

**新增的是少数末端机会的净分比较，尚未增强前段七对构建。**比较双方使用相同的v10规则；抓打圈、公开牌去重、并发和时限修复属于共同基础，不能记为候选策略独有收益。

1. **增加可选条件结算事实。**唯一规则模块对当前胡及候选弃牌后的下一次普通自摸给出分值、爆头证明和覆盖状态。使用 `ValueAnalysisLimits(2048, 128)` 限制展开量与分组数；先取得紧急动作，原始预算不延长。未知或未完整覆盖时不把估值当成确定结论。
2. **允许有条件放弃当前胡。**设现在胡的本人净分为G，弃牌后下一次普通自摸的最低本人净分为U；规则须完整证明该等待可爆头，且U高于G。仅当 `p×U−c×G > 1.10×G` 时把升级弃牌排在胡前。p是等待到下一摸的离线生存估计，c是已经包含失败频率的无条件支付倍数；不再次乘失败概率。
3. **保持已证明的爆头等待。**在真实吃碰窗口，已有完整普通自摸爆头等待证明时优先合法过牌，避免鸣牌改变等待前提。代码根据当前观察判断，不要求本地保存“上一回合曾主动弃胡”的标记；所以这也可能改变本来就处于爆头等待的响应。

当前低威胁组（对手最后一弃不是白且均少于三副公开副露），余牌40–63时p=0.83、至少64时p=0.92，c均为0.10；余牌包含保留区。其他风险组不启用主动弃胡升级。每次只比较下一次普通自摸，之后如需再飘则重新判断，不提前累加多次飘的积分。

例如现在胡10分，下一摸最低20分，p=0.83时比较值为 `0.83×20−0.10×10=15.6`，高于11分门槛才等待。它没有保证一定等到下一摸；确认批实际发生过他家先胡的支付。

V2权重、普通非等胡弃牌排序和原有杠评分保持；候选未新增七对固定奖励、多步搜索、模型或线上模拟。新校准适用范围为底分1、`YouCaiBiKao=false`、`hangma-mvp-v10-public-counts`及默认V2模拟对手池。`YouCaiBiKao=true`仍由规则模块正常支持，但当前风险表未在该配置校准，等胡候选入口会拒绝套用。详细证据见[当前复验报告](../../review/v2-hu-upgrade-v10-2026-09-09/README.md)。

## 4. 如何指定

### 自由赛、单身份赛事

在已有私有配置里显式设置这一项，保留原Token、赛事和运行参数：

```json
{"strategy": "weighted_heuristic_v2"}
```

这是配置修改片段，不是完整运行配置。自由赛入口读取JSON，没有 `--strategy` 参数：

```bash
# 配置中的Token继续使用原有私有文件或环境变量。
.venv/bin/python scripts/run_auto_match.py --config .private/auto-match.json
.venv/bin/python scripts/run_participant.py --config .private/participant.json
```

要选普通弃白保护变体，将值改为 `weighted_heuristic_v2_white_guard`。当前不要把 `v2_hu_upgrade_v1` 填进自由赛或正式赛事配置：这些模式尚不接受它。

### 四身份测试房

通常顶层设置V2，只为待测身份覆盖策略。可直接复制[一候选三V2模板](../../configs/test-room-v2-hu-upgrade.example.json)，填写新测试房与私有Token来源；使用该候选须从实验分支运行。

```bash
.venv/bin/python scripts/run_test_room.py --config .private/test-room.json --once
```

模板的A身份为 `v2_hu_upgrade_v1`，B/C/D继承顶层V2。`M`、`Rounds`及规则开关由平台房间配置决定；模板不意味着已经创建或授权新房间。

### 离线完整桌赛

实验配置的 `baseline_policy.name`、`challenger_policy.name` 和对手声明的 `name` 使用本表枚举；`policy_id`只是结果中的身份标签，不能用它切换实现。例子：

```json
{
  "challenger_policy": {
    "policy_id": "candidate-v2-hu",
    "name": "v2_hu_upgrade_v1",
    "weights": {"upgrade_weight": 1}
  },
  "value_limits": {"max_expansions": 2048, "max_routes_per_candidate": 128}
}
```

该片段需合并进完整实验配置；参考[当前开发配置](../../review/v2-hu-upgrade-v10-2026-09-09/experiments/development.json)。正式新实验必须另用预登记的新种子和输出目录，不能把旧确认集继续当成未见样本。`upgrade_weight=0`关闭等胡增强，V2底座精确返回V2；对 `hu_upgrade_v1` 则返回一次摸牌底座，二者不同。分值候选必须显式开启 `value_limits`，两个等胡名称还受规则和对手池范围核对。

## 5. 下一步怎样优化

**仍有改进空间，但应逐项证明净分改善，不靠增加策略名或只看最大番数。**本批已结束，不追加同一确认集或继续扫权重。开发优先级如下；第一项已完成独立开发验证并停止；其余仍为计划，不是已实现的枚举。

| 优先级 | 具体改动 | 为什么值得做 | 验证与退出条件 |
| --- | --- | --- | --- |
| 1（已验证停止） | 已吃碰、没有立即胡时，比较合法续白与普通弃牌的下一摸净分；首版只覆盖链已知、两条路线均有完整任意听证明的窗口 | 主线合成见证中，打3条断链只得×2，打白续飘可得×8/16；现有弃白惩罚会压掉好路线。两者都等下一次自摸，较容易比较 | 复用现有规则分值，不复制计番；先验证真实短前缀、未知事实退路和总耗时，再在新开发请求检查频率。先与V2独立比较，通过后再验证与等胡增强的组合；组合可能因优先过牌而减少此类机会，不能直接叠加两项收益 |
| 2 | 更早比较七对、豪华七对与标准型路线，并把吃碰或杠导致的路线损失纳入选择 | 当前等胡增强只优化已经可胡的尾段；仍未回答前几次弃牌如何保留高价值牌型，固定杠奖励也未反映补牌与失去七对之间的取舍 | 先在历史机会中提取少量可见状态，使用同一规则做有界进张与后续弃牌评估；同时计算成牌速度和失败支付。不用“一律保对子／禁杠”替代估值；费用过高或新开发净分不正即停止，不能只用未来牌墙证明当时应选某动作 |
| 3 | 将等胡风险按普通弃牌升级／财飘、当前番数等少量可见因素细化 | 确认中余牌40–63组生存比例77.78%，低于校准值0.83；失败集中在1番普通升级，说明分组仍粗 | 重新收集独立校准样本，保留每格样本门槛；不直接用已看过的确认标签重调后又宣称确认通过。失败支付小不代表必须禁等，最终仍看完整桌赛净分 |

每轮只保留一个明确改动的候选，固定规则、底座、参数、开发集与独立确认集，采用同牌山换座、完整八单局桌赛和按根组聚类区间；先检查规则与计算预算，再投入模拟。测试房在确需验证新增线上行为时申请，不用一次房间的随机座位总分替代策略对照。达到效果和运行门禁后再由人审核是否替换稳定选用值；没有通过的候选保留为研究记录。

### 吃碰后续飘候选的实际结论

`v2_claim_piao_v1` 的 `weights.continuation_weight` 为1时启用、0时精确返回V2；必须在离线实验显式提供 `value_limits` 才能获得增强所需事实。它只覆盖已有财飘链，不改变此前进入财飘或吃碰的决定，没有线上入口。

新32根、四次换座、双方各128完整八单局桌赛中，候选43,100次决策、1,056个无摸牌弃牌窗口，目标财飘窗口和改变动作均为0。净分、独占第一和胡牌分布与V2相同，故按预登记停止，独立确认集未运行。完整证据见[续飘专项](../../review/v2-claim-piao-2026-09-09/README.md)。下一步优先调查更早的牌型路线选择，不直接把续飘与等胡叠加。
