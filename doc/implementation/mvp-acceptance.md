# 第一阶段 MVP 验收标准

> 目标：证明 Bot 能用四个测试房间 Token 和一个测试赛事身份全自动、按时、可恢复、可审计地运行。策略强度优化不是本阶段放行条件。

## 1. 发布门禁

以下门禁全部通过才称为“可参加测试赛事 MVP”。官方测试赛事已提供，因此不是可选项。

| 门禁 | 环境 | 必须证明 |
| --- | --- | --- |
| C1 契约 | 本地 | 接口基线类型可导入；封闭结果和依赖方向未破坏 |
| C2 规则 | 本地 + `fan-calc` | 完整动作族已接入；紧急路径独立；差异有明确降级和审计 |
| C3 生命周期 | Fake | 报名、到位、阶段空窗、淘汰、候补、重赛、终态和新增场次 |
| C4 提交安全 | Fake 故障注入 | 409 可降级；模糊结果同窗不追加；截止时间不因刷新延长 |
| C5 四身份冒烟 | 官方测试房间 | 4 Token × `M=1/Rounds=1` 全自动完赛，目录隔离 |
| C6 目标并发 | 官方测试房间 | 每身份按 `active_games` 处理目标 `M/Rounds`，无请求饥饿 |
| C7 测试赛事 | 官方测试赛事 | 从初始化到参赛者终态无需我方人工确认、选牌或重启 |
| C8 审计 | 所有环境 | 关键动作信封可关联，验证器报告完整或诚实标记降级 |
| C9 恢复 | Fake + 官方测试环境 | 网络波动、进程重启、单场异常和磁盘异常可恢复或安全退出 |

## 2. 功能验收

- 运行前检查指南版本、规则配置、运行模式、目标赛事和脱敏身份。
- 第一阶段规则引擎能够枚举出牌、吃、碰、各类杠、胡和过；财神、有财必拷响、抓打圈、爆头/飘链及结算进入同一规则模块。
- 规则分支故障按动作权重和剩余合法候选降级；最终紧急路径为响应过、抓打牌或普通手牌最右一张。
- 一个身份以 `active_games` 为权威并发运行不超过 `config.M` 场；新增和消失的 `game_id` 能动态建立/回收会话。
- 阶段间 `active_games=[]` 不退出；身份淘汰正常退出；赛事 `finished/closed/void` 正常退出。
- 组委会/admin 推进阶段可以发生在外部，但我方程序全程不要求人工动作、确认、重启或继续。

## 3. 安全和时间验收

- 每个动作窗口先准备紧急候选，再运行增强逻辑。
- 1 秒响应窗口不调用在线 LLM、复杂搜索或外部规则服务。
- 相同窗口任意时刻最多一个在途 POST。
- 只有明确拒绝且权威刷新确认同窗仍开放时，才可提交下一候选。
- POST 超时、断连或结果不明时，旧窗口追加提交次数为 0。
- 409 重新规划复用原始三个截止时间；超过 `latest_send_at_monotonic` 的 POST 发送次数为 0。
- GET 恢复、长轮询、排名刷新和审计不会抢占动作提交所需资源。

具体延迟阈值在取得目标部署机器基准后固定；在此之前至少报告端到端 P50/P95/P99、超时数、服务端自动动作数和最小剩余安全余量，禁止只报告平均值。

## 4. 审计验收

每次运行必须生成 manifest、生命周期、身份/场次记录和汇总。以下链路可以用关联键无歧义连接：

```text
权威观察 → 规则候选/降级 → 策略排序 → 提交 intent
→ 提交 outcome/恢复 → 场次结果 → 参赛者结果
```

- 每个实际 POST 有唯一 `decision_id + attempt_no`。
- 高优先级 intent/outcome 缺失时，验证器失败或报告 `audit_degraded`，不得默认为成功。
- 四身份相同 `game_id` 不串写。
- Token、`Authorization`、Cookie 原文扫描结果为 0。
- 中断阶段尝试带 `stage_attempt_id` 和作废标记，不混入有效成绩。

## 5. 最小测试矩阵

| 类别 | 最少案例 |
| --- | --- |
| 窗口 | 摸牌出牌、碰、吃、响应过、可胡、抓打圈 |
| 提交 | 200、409 同窗、409 已关窗、超时、断连、未知 5xx、过截止未发送 |
| 同步 | 重复 seq、seq 缺口、`gap=true`、兼容未知事件、关键未知事件、全量替换 |
| 赛事 | registering、running、stage_done、stage_open、淘汰、crashed、finished、closed、void |
| 并发 | 一个 Token 多场、四 Token 隔离、同场重入、一个场次崩溃 |
| 资源 | 429、慢 GET、30 秒长轮询取消、磁盘慢/满、队列满、进程重启 |
| 规则 | 每类动作正反例、规则分支异常、紧急路径、计分对拍、牌与积分守恒 |

## 6. 验收证据包

每次候选发布保存：代码提交、配置（不含 Token）、指南快照、规则版本、测试报告、官方测试房间 ID、官方测试赛事 ID、审计验证报告、延迟与错误汇总。官方只提供赛后复盘时，证据以本地实时快照/事件审计和赛后结果为主，不假设存在额外正式赛事牌谱下载接口。
