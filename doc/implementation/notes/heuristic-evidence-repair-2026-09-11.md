## 3. 下一步按这个顺序做

1. **重采爆头就绪案例，先做 64 个开发牌山根。**增加每局、每桌采样上限，报告捕获数量、不同动作数、未匹配原因及每根分布；仍登记最小牌墙间隔，不称作全量决策普查。先审查少量真实动作差异，再决定是否扩样。这个开发批次用于定位，不以统计显著作为采样器通过条件。
2. **检查路线是否需要持续配合。**当前分支比较只替换一次动作，之后四家全部用 V2 续打到本局终局。先核对弃牌后是否保留爆头、飘杠链和合理后续动作；若收益依赖持续选择，就定义一个完整候选后再做完整桌赛，不能用单次替换结果否定整条路线。
3. **补强手差异案例，再只实现一个改进候选。**从[同桌差距复核](../../../review/heuristic-gap-audit-2026-09-10/README.md)继续，按白板资源、庄位、牌效配平，抽查和牌价值与支付差异。普通弃牌二阶牌效仍是优先候选方向；只有确认现有决策的具体不足后才动评分。对手动作是诊断线索，不能直接作最优标签。
4. **开发比较通过后，再做独立确认。**保持完整八局桌赛、同牌山和换座，至少覆盖三个 V2 与三个等胡升级策略两类对手池；先固定候选、规则、指标、种子和样本量。确认样本须与所有已用于调参的数据分离，不反复查看结果后追加到显著。新版脚本只自动核对所引用开发批次，历史已探索种子还需登记核查。

若上述有界探索仍不能给出可重复的候选优势，再将主要研发资源转向候选结果模型（`CandidateOutcomeModel`，由可见观察及候选动作预测本局积分结果）。现在可以准备完整观察与标签导出；18,588 个旧窗口尚不等于训练输入和反事实标签已经齐备，不能直接以此启动正式训练。

## 4. 不要混淆这些结论

- 采样扩充 `1 → 8` 证明旧研究漏掉窗口，不说明爆头偏好一定有效；原子集上的负值也不需要删除。
- 新门禁的零差异冒烟仅验证相同策略应产生相同结果。`passed=true` 伴随 `performance_validated=false`、`release_authorized=false`。
- 模拟逻辑时钟的零超时不能替代真实 1 秒/3 秒、多场并发及降级验收。
- 跨机器的 Python 或本地扩展二进制发生变化时，当前严格源码/环境冻结检查可能拒绝复用开发结果；需要重新建立对应环境的开发基点，不能绕过检查合并确认结果。
