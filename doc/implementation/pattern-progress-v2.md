# 分牌型推进事实与下一阶段评价

规则侧补全每种牌型的活进张，用于比较保留大牌路线的代价。首个只看距离、容忍5%总进张损失的候选在独立确认中每桌仅+0.0625，未达标；不据此自动放宽阈值。先恢复原计算中被丢弃的分牌型进张，再比较逐牌的推进与重合。

## 兼容数据契约

现有 `CandidateFacts` 尾部增补下列可选字段，`HAND_PROGRESS` 才携带有效牌集合。旧字段、既有最佳后续弃牌和最优向听保持原样。

| 字段 | 类型和语义 |
| --- | --- |
| `standard_useful_tiles` | 可空 `Tuple[UsefulTileFact, ...]`；同一等待手牌中能降低普通型向听的牌及可见未见数量 |
| `seven_pairs_useful_tiles` | 同上，针对七对；已有任意副露不适用 |
| `pattern_progress_note` | 可空字符串；新增牌型集合的计数缺证据或失败说明，不污染旧综合事实完整性 |

`None` 表示未枚举、不适用或该集合的公开计数无法完整确认；`()` 表示已枚举且没有有效牌。数学有效但公开已耗尽的牌可以保留，数量为0。未见牌包括他家暗牌，不能直接除以剩余牌墙张数解释成摸到概率。

新集合可能包含原综合有效牌以外的牌。若仅这些牌的供牌去重未知，只将受影响的新集合置空并记录原因；原综合向听、有效牌、另一完整集合继续可用。不能新增一个可选分析，反而使稳定V2的旧事实失效。

审计仍为 codec v1；非空集合写数组，空元组写 `[]`，None省略键；缺键/null读None。新集合与先前普通型/七对距离在完整请求中一起往返，旧记录不能补算成新事实。

## 计算和信息边界

`hand_analysis` 在既有34种进张循环中保留两种牌型分别计算的结果，不新增标准型或七对数学调用。综合有效牌及其白板保险维持原样；分牌型白板只使用实际数学结果，不复制综合保险。持满4张的第五张始终不进入集合。当前已胡时不扩展进张搜索，紧急路径不计算这些事实。

吃碰仍用同一个原最佳后续弃牌的等待手牌，不为各牌型分别挑牌再拼结果；杠仍是补牌前事实。策略和离线评价消费新字段，不访问他家手牌、未来牌墙，不实现第二套向听算法。

## 评价顺序

1. 先检查相同牌型距离下的活进张差异和普通型/七对交集，补齐旧案例对较慢路线的盲区。
2. 构造逐进张不退步的选择题：每种可见剩余牌都不使两条路线更远；这是推进事实比较，仍不是长期净分支配证明。
3. 对有速度代价的选择使用完整续打，并明确续打策略是否持续保留目标路线；不能强迫首步保七对、随后全部用会拆七对的策略，就把结果称为该路线的最优价值。
4. 自然发牌完整桌赛使用新开发/确认种子；旧确认集只能作历史对照。任何候选仍需原净分、第一名比例与运行门禁，不自动上线。
